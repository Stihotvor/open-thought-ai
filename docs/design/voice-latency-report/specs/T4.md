# T4 Audio script

Resolved: defaults `en_US-amy-medium`, `pl_PL-gosia-medium`, `uk_UA-ukrainian_tts-medium` (Piper, through speaches as `speaches-ai/piper-<voice>`), base URL `http://localhost:8000/v1`, all overridable by flags. Marked "verify" in the guide.

## Context
The harness needs 16 kHz mono s16le WAV input made from the phrase text, with no committed audio (B3, T4, T5, E4).

## Technical Approach
Create `server/scripts/make_phrase_audio.py` and `server/tests/test_make_phrase_audio.py`.
- Read `docs/research/m3-phrases.json` (T3). Write `<out>/<lang>/<id>.wav`. Default out dir is git-ignored.
- First step: call the speaches health endpoint. If it fails, print a clear message and exit non-zero before any synthesis call (E4).
- For each phrase, call the speaches speech endpoint with the Piper voice of the language. Convert the result to 16 kHz mono s16le with the standard `wave` module or the existing `ota_server.audio` helpers.
- The HTTP client is injected, so the test uses a fake.

## Acceptance Criteria
```gherkin
Scenario: speaches is down
  Given a fake HTTP client whose health call fails
  When the script main runs
  Then the exit code is non-zero, the message names speaches, and the fake saw no synthesis call

Scenario: WAV format
  Given a fake client that returns a 22.05 kHz WAV
  When the script writes a phrase
  Then the file has 16000 Hz, 1 channel and 16-bit samples

Scenario: one file per phrase
  Given the 90 phrases and a fake client
  When the script runs
  Then 90 WAV files exist, 30 in each language directory
```
