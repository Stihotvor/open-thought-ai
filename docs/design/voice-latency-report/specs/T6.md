# T6 latency_report

Resolved: the harness parses the timing line right after each turn and writes its fields into the same JSONL record. The report reads only the JSONL. Warm-up is the first record of each `run` value. WER split: lower case, strip punctuation (`str.isalnum` or space), split on whitespace.

## Context
The report turns captured lines into p50 and p95 per stage and language, against the budget in `docs/architecture.md` (B1, B2, T7, M3, E1, E3, E5, F3, F4).

## Technical Approach
Create `server/src/ota_server/latency_report.py` (`python -m ota_server.latency_report`), `server/tests/test_latency_report.py`, and the data files `server/tests/data/latency_sample.log` and `latency_sample.jsonl`.
- Read lines with `parse_line` (T1) and the JSONL from T5. Output Markdown.
- Percentiles: one fixed method (linear interpolation, as `statistics.quantiles` with `method="inclusive"`). Name it in the report.
- Per language: drop the first turn of each run (warm-up, F3). Failed turns are counted by code and left out of the numbers (E1). Missing stages are counted (E3).
- Budget column, with a footnote that the budget assumes per-sentence streaming: `vad` to "Upload tail + VAD end" 0.2 s, `stt` 1.2 s, `chat_first_sentence` 2.0 s, `mod_reply` 0.5 s, `tts1` 0.8 s. `mod_transcript`, `chat_full` and `selftest` have no budget row. Show "not measured" for the upload tail and "Network + device buffer" 0.3 s.
- Show `chat_full` minus `chat_first_sentence` as the time streaming could save. Show WER per language from the STT text and the phrase text (E5). Add a note that the input is synthetic Piper audio (F4).
- Pure functions on strings, so the test needs no I/O except the sample files.

## Acceptance Criteria
```gherkin
Scenario: exact percentiles
  Given the sample log and JSONL
  When the report is built
  Then p50 and p95 per stage and language equal the values fixed in the test

Scenario: warm-up left out
  Given a sample where the first turn is 9000 ms and the rest are 4000 ms
  When the report is built
  Then the p50 is 4000 ms

Scenario: failures counted
  Given a sample with one "no_speech" and one "rate_limited" turn
  When the report is built
  Then the report lists each code with count 1 and the percentiles exclude both

Scenario: missing stages
  Given a turn with no chat_first_sentence
  When the report is built
  Then the report shows the missing count 1 for that stage

Scenario: budget and notes
  Given any sample
  When the report is built
  Then each budgeted stage shows its budget, the footnote about streaming is present, the synthetic-input note is present, and unmeasured rows show "not measured"

Scenario: streaming gap
  Given chat_first_sentence 1000 and chat_full 3000 for a turn
  When the report is built
  Then the report shows 2000 ms as the time streaming could save

Scenario: WER
  Given STT text "hello wor" for the phrase "hello world"
  When the report is built
  Then the WER for that language is 0.5
```
