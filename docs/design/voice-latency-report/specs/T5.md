# T5 latency_run harness

Resolved: build roles with `main.voice_roles(model_env())` and the client with `ModelClient(roles, make_http_client())`, as `main.py` does. The STT text comes from the `notify` callback that the harness passes to the pipeline.

## Context
The owner needs one command that runs the phrases through `VoicePipeline` with real endpoints and keeps the stage lines (B3, T6, E2, F3).

## Technical Approach
Create `server/src/ota_server/latency_run.py` (`python -m ota_server.latency_run`) and `server/tests/test_latency_run.py`.
- Args: `--lang`, `--audio` (alias `--audio-dir`), `--out`, `--pause` (seconds between turns), `--resume`.
- Build `VoicePipeline` and its `ModelClient` from `OTA_<ROLE>_*`. Tests inject a fake client and do not read the environment.
- Play the WAV files of one language in sorted id order. Read each WAV to PCM with the audio helpers. Drain the turn generator. Sleep `--pause` between turns (the sleep function is injected).
- Capture the `turn.latency` line with a logging handler on the pipeline logger. Write it to `<out>/<lang>.log`.
- Append one JSONL record per turn to `<out>/run.jsonl` (schema in decision.md "Run record"): `phrase_id`, `language`, `code`, `stt_text`, line `id`. The STT text goes in this file only, not in the log (F5).
- `--resume` reads the JSONL and skips done phrase ids. A turn that ended with `rate_limited` is not done.

## Acceptance Criteria
```gherkin
Scenario: order and pause
  Given fake providers, 3 WAV files for "en" and pause 2
  When the harness runs
  Then the turns run in id order and the fake sleep was called twice with 2

Scenario: lines and JSONL
  Given a completed run of 3 phrases
  When the test reads the output files
  Then the log has 3 "turn.latency" lines and the JSONL has 3 records with phrase_id, language, code and stt_text

Scenario: failed turn is recorded
  Given a fake chat that fails for phrase p02
  When the harness runs
  Then the JSONL record for p02 has code "llm_failed" and the run goes on

Scenario: resume
  Given a JSONL with p01 and p02 done
  When the harness runs with --resume
  Then only p03 is played and the files keep the earlier records

Scenario: rate-limited turn is not done
  Given a JSONL record for p02 with code "rate_limited"
  When the harness runs with --resume
  Then p02 is played again
```
