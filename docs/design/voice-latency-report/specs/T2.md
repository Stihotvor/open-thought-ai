# T2 Pipeline stage marks

Resolved: `VoicePipeline` keeps its own turn counter (`self.turns += 1` per call). No session or `ReplySource` change.

## Context
Stage times must come from the real `VoicePipeline` turn, so device turns and the harness give the same data (B2, T2, T3, F1, F5, M2, M4, M5).

## Technical Approach
Edit `server/src/ota_server/pipeline.py`. Add `server/tests/test_pipeline_latency.py` with fake providers.
- In `__call__`, create a `StageTimer` (T1) before `speech_only`. Mark: `vad` after `speech_only`; `selftest` only when `check_moderation` runs the self-test; `stt` after `transcribe`; `mod_transcript` after the transcript `moderate`; `chat_full` after the chat join; `mod_reply` after the reply `moderate`; `tts1` after the first `speak` chunk is ready (first `speak` call plus `wav_to_pcm`).
- `chat_first_sentence`: replace the `"".join([...])` with a loop that notes the first time `SENTENCE_END` matches the text so far. The reply text stays the same. If no sentence end appears, the stage is missing (E3).
- Stamp `latency_ms` at the first yield. Log one `turn.latency` line with `format_line` in a `finally`. A failed turn logs its `TurnError` code and no latency.
- `tts1` must be marked inside `speak` or from the timer passed to it. Keep `speak` behaviour unchanged.
- Do not log text, only times, code and id (F5).

## Acceptance Criteria
```gherkin
Scenario: a good turn logs all stages
  Given fake providers and a reply with two sentences
  When one turn runs to the end
  Then one "turn.latency" log record has latency_ms and vad, stt, mod_transcript, chat_first_sentence, chat_full, mod_reply, tts1

Scenario: the self-test stage shows on the first turn only
  Given a new pipeline
  When two turns run
  Then the first line has selftest and the second line has none

Scenario: a failed turn logs its code
  Given a fake chat that raises ProviderError
  When the turn runs
  Then the line has code "llm_failed" and no latency_ms

Scenario: no text in the log
  Given a transcript "SECRET-Q" and a reply "SECRET-A"
  When one turn runs
  Then no log record at info level contains "SECRET-Q" or "SECRET-A"

Scenario: reply without a sentence end
  Given a reply "ok" with no end mark
  When the turn runs
  Then chat_first_sentence is missing from the line and the turn still gives audio

Scenario: timer error does not break a turn
  Given a StageTimer that raises in mark
  When the turn runs
  Then the turn yields its audio chunks

Scenario: overhead is small
  Given fake providers with no delay
  When the same turn runs with and without timing
  Then the difference per turn is 1 ms or less

Scenario: behaviour is unchanged
  Given the existing pipeline tests
  When pytest, ruff check and mypy run
  Then all report 0 errors
```
