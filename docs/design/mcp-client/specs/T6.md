# T6: Wire mcp_sources into lifespan, gateway and session; e2e test and gate

## Context
The pieces from T1 to T5 must reach the hub of each device session without changing the hub, the chain or the pipeline (B2, D10). This task wires the sources, proves the full voice turn and runs the gate. It serves B1, B2, E1, T10, M5.

## Technical Approach
Edit these places:
- `server/src/ota_server/main.py` `lifespan` (lines 29-34): inside the `AsyncExitStack`, after `reply_source` is set, call `load_servers(settings.mcp_servers_file)` (T1), then `McpRegistry.start(configs, stack)` (T5), and store the result in `application.state.mcp_sources`. With no file the list is empty and nothing else changes. Keep this in a small helper `start_mcp_sources(settings, stack)` next to `start_reply_source` (line 20).
- `server/src/ota_server/gateway.py` `device_endpoint` (lines 81-86): read `ws.app.state.mcp_sources` and pass `mcp_sources=...` to `DeviceSession`.
- `server/src/ota_server/session.py` `DeviceSession.__init__` (lines 60-66): add the parameter `mcp_sources: Sequence[ToolSource] = ()`. Line 82 becomes `McpHub([DeviceSource(self.ws.send_json, self.pending), *mcp_sources])`.
- Many sessions share the same source objects. They share the connections (T6 owner decision, E7).
- Tests `server/tests/test_session.py` and `server/tests/test_gateway.py`: add a case that the hub of a session holds the given source tools, and that the default is device tools only. In `test_gateway.py`, set `app.state.mcp_sources` in the test fixture if the existing tests build the app without the lifespan.
- `server/tests/test_mcp_e2e.py`: a full voice turn with a fake http MCP server (`mcp_fakes.py`, T3) and a fake chat. The shared `Endpoint` in `server/tests/fakes.py:63` returns a fixed reply text, so write a small chat-endpoint wrapper in `test_mcp_e2e.py` that answers the first chat request with a tool call to `<server>__echo` and the second with the final text. Check the real tool-call SSE format in `pipeline.py` and the device-tools tests before writing it.
- Child-gone check: use `assert_pid_gone` from `server/tests/mcp_fakes.py` (T3) with the PID from the stdio server `pid` tool, taken before app shutdown.
- Run `server/scripts/gate.sh` at the end. Coverage must be at least 90 %. Fix gaps with tests, not with excludes.

## Acceptance Criteria
```gherkin
Scenario: Voice turn calls an MCP tool

  Then ruff reports 0 findings and mypy reports 0 errors
```
