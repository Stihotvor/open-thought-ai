# T3: SdkConnection adapter, mcp==1.30.0 pin and fake servers for http, sse and stdio

## Context
`SdkConnection` is the only file that imports the MCP SDK (D2, D3, D4). It implements the `McpConnection` port from T1 for all three transports. It serves B1, T2, T7, T9, M1, M4, D9 and D11. T4 adds reconnect to the same file, so keep the structure open for it.

## Technical Approach
Add `mcp==1.30.0` to `server/pyproject.toml` dependencies and refresh `server/uv.lock` (D3). The lock must hold exactly that version. The server already has `httpx`.

`server/src/ota_server/mcp/adapters.py`:
- Module constant `STOP_TIMEOUT = 5.0` (seconds). `close()` reads it at call time, so tests patch it small with `monkeypatch.setattr`.
- `class SdkConnection` implements `McpConnection`. Build it with `SdkConnection.open(config: McpServerConfig, policy: ConnectionPolicy) -> SdkConnection`, an async factory.
- Owner task (D4): `open` starts one task. In that task: call `policy.before_connect(config)` (D11), enter the transport context (`streamablehttp_client` for `http`, `sse_client` for `sse`, `stdio_client` with `StdioServerParameters` for `stdio`) and `ClientSession` with `async with`, call `initialize()`, set a `ready` event, then wait on a `stop` event. The task leaves the same blocks in the same task (anyio rule). `open` waits for `ready` or for a task failure, and re-raises the failure. A `ConnectionDenied` from the policy blocks the connect and propagates.
- The policy headers go to the http and sse transport as `headers`. For `stdio` the policy may only deny (D11). Ignore any returned headers.
- `list_tools` maps SDK tools to `RawTool(name, description or "", inputSchema)`.
- `call_tool` uses the shared `ClientSession.call_tool` directly from the caller task, with no queue (E7). It maps `isError` and the content parts to `RawResult`: `TextContent` is `("text", text)`, `ImageContent` is `("image", "")`, others are `("resource", "")`.
- Stdio env (D9, T7): pass `StdioServerParameters(command, args, env=config.env)`. The SDK merges `get_default_environment()` with it. Do not add `os.environ`.
- `close()` (D9): set `stop`, wait up to `STOP_TIMEOUT` for the owner task. After the deadline cancel the owner task and await it. Do not kill a PID. `close()` is idempotent and never raises.
- Test-only way to force the deadline path: `open` takes an optional keyword `transport_factory` (default: the real SDK transport chooser). The test passes a factory that returns an async context manager whose `__aexit__` blocks on a never-set event until it is cancelled. This holds the owner task in its `async with` after `stop` is set, so only the cancel path ends it. For the stdio deadline test the factory wraps the real `stdio_client`: it enters the real transport, then blocks in `__aexit__` before it calls the real `__aexit__`. The cancel then runs the SDK cleanup, which stops the child.

Test support in `server/tests/`:
- `mcp_fakes.py`: a helper that starts a `FastMCP` fake server with a tool `echo(text)` and a tool `hidden` on `127.0.0.1` with a free port, using uvicorn in a background task, for `http` and `sse`. It has a stop and a restart-on-same-port method (T4 uses it). It also holds the one shared helper `assert_pid_gone(pid: int, timeout: float = 3.0)`: poll every 0.05 s until `os.kill(pid, 0)` raises `ProcessLookupError`, and fail the test when the timeout passes. T4, T5 and T6 use it too.
- `mcp_stdio_server.py`: a stdio `FastMCP` script with the tools `echo`, `env_dump` (returns its environment variable names as text) and `pid` (returns `os.getpid()` as text).

Tests in `server/tests/test_mcp_adapters.py`. Use the `config` of each transport and `AllowAll` policy unless the scenario says otherwise. A test that needs the child PID calls the `pid` tool before `close()`.

## Acceptance Criteria
```gherkin
Scenario Outline: List and call over each transport
  Given a fake FastMCP server on <transport>
  When SdkConnection.open connects, list_tools runs and call_tool("echo", {"text": "hi"}) runs
  Then list_tools holds the tool "echo"
  And the result has is_error False and a text part "hi"
  Examples:
    | transport |
    | http      |
    | sse       |
    | stdio     |

Scenario: Stdio child has a clean environment
  Given the test process env holds OTA_DEVICE_ID, MCP_SECRET_X and OPENAI_API_KEY
  And a stdio entry with env {"FOO": "bar"}
  When the child tool env_dump runs
  Then the names include FOO and PATH
  And the names include none of OTA_DEVICE_ID, MCP_SECRET_X, OPENAI_API_KEY

Scenario: Policy runs before connect
  Given a ConnectionPolicy that records the call order
  When SdkConnection.open runs
  Then before_connect ran before the transport was opened

Scenario: Policy denies a connection
  Given a ConnectionPolicy whose before_connect raises ConnectionDenied
  When SdkConnection.open runs
  Then it raises ConnectionDenied
  And no transport was opened

Scenario: Close leaves no stdio child
  Given an open stdio connection and the child PID from the "pid" tool
  When close runs
  Then assert_pid_gone(pid) passes: os.kill(pid, 0) raises ProcessLookupError within 3 s

Scenario: Close when the stop deadline passes
  Given STOP_TIMEOUT patched to 0.2
  And a stdio connection opened with a transport_factory whose exit blocks until cancelled
  And the child PID from the "pid" tool
  When close runs
  Then close returns within 0.2 s plus 2 s
  And assert_pid_gone(pid) passes

Scenario: Pin
  Given server/pyproject.toml and server/uv.lock
  When the test reads them
  Then both name mcp at version 1.30.0
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
