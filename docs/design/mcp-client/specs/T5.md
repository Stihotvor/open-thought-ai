# T5: McpRegistry: parallel start with 5 s deadline and shutdown

## Context
The server connects to all configured servers once at startup and shares the sources across device sessions (T6, D10). A down server must not block or stop the start (E1). Shutdown must leave no stdio child (F4, M4). This task serves B1, E1, F4, M4 and D10.

## Technical Approach
Create `server/src/ota_server/mcp/registry.py`.

`McpRegistry`:
- Module constant `CONNECT_TIMEOUT = 5.0`, read at call time so tests patch it small.
- `async def start(configs: Sequence[McpServerConfig], stack: AsyncExitStack, policy: ConnectionPolicy = AllowAll(), tool_filter: ToolFilter = AllowAll(), connect=SdkConnection.open) -> list[McpSource]`. The `connect` argument is an injection point for tests, with the signature of `SdkConnection.open` (T3).
- Connect all servers in parallel (`asyncio.gather` or `TaskGroup`), each under `asyncio.timeout(CONNECT_TIMEOUT)` (D10). For each server: `conn = await connect(config, policy)`, then `McpSource.build(config, conn, tool_filter)` (T2).
- A server that fails or hits the deadline logs a warning with the server name and no secret or URL userinfo. It gets no source and stays off until the server restarts. No background retry (D10). If the connect succeeded but the source build failed, close the connection.
- Register `conn.close` on the `stack` (`stack.push_async_callback`) as soon as a connection is made, so lifespan exit closes all sessions (F4). Closing runs for all connections, even if one close fails.
- Keep source order equal to config order.
- A source with 0 admitted tools is dropped and its connection is closed (D10). Log an info line with the server name.

Tests in `server/tests/test_mcp_registry.py`. Use the fakes from T3 for real servers, and an injected `connect` that hangs for the deadline test (patch `CONNECT_TIMEOUT` small there). One test asserts the default is 5.0. Child-gone checks use `assert_pid_gone` from `server/tests/mcp_fakes.py` (T3) with the PID from the stdio server `pid` tool, taken before shutdown.

## Acceptance Criteria
```gherkin
Scenario: One server down, one up
  Given two configs, one with an http fake server up and one pointing to a closed port
  When McpRegistry.start runs
  Then it returns 1 source for the up server
  And a warning names the down server
  And the up source lists its allowlisted tools only

Scenario: Hung server hits the deadline
  Given a connect function that never returns for one config and CONNECT_TIMEOUT patched to 0.5
  When McpRegistry.start runs
  Then start returns within 0.5 s plus 0.5 s
  And the hung server has no source

Scenario: Default deadline
  Given the module registry
  When the test reads the constant
  Then CONNECT_TIMEOUT is 5.0

Scenario: Servers connect in parallel
  Given 3 configs whose connect each waits 0.3 s
  When McpRegistry.start runs
  Then it returns 3 sources in config order in less than 0.8 s

Scenario: No configs
  Given an empty config list
  When McpRegistry.start runs
  Then it returns an empty list

Scenario: Source with no admitted tools is dropped
  Given a server whose allowlist matches no listed tool
  When McpRegistry.start runs
  Then it returns no source for that server
  And its connection was closed

Scenario: Shutdown closes everything
  Given a started registry with 1 http and 1 stdio server on an AsyncExitStack and the stdio child PID from the "pid" tool
  When the stack closes
  Then every connection was closed
  And assert_pid_gone(pid) passes: os.kill(pid, 0) raises ProcessLookupError within 3 s

Scenario: One close fails
  Given two connections and the first close raises
  When the stack closes
  Then the second connection was still closed
```
