# T1: MCP port, hooks and config loader with Settings field

## Context
External MCP servers become hub tool sources (B1, B2). This task builds the SDK-free base that T2 to T6 use: the connection port, the #31 hooks and the JSON config loader. It serves T3, T4, T5, T8, E6, D1, D2, D8 and D11. B3 needs the hooks seam now, so #31 adds checks without a client rewrite.

## Technical Approach
Create the package `server/src/ota_server/mcp/`. Only `adapters.py` (T3) imports the `mcp` SDK. `port.py`, `hooks.py` and `config.py` must not import it.

`mcp/port.py` (exact names, the contract for T2 to T5):
```python
@dataclass(frozen=True)
class RawTool:
    name: str
    description: str
    schema: dict[str, Any]

@dataclass(frozen=True)
class RawResult:
    is_error: bool
    parts: list[tuple[str, str]]   # (kind, text); kind is "text", "image" or "resource"; text is "" for non-text

class McpConnection(Protocol):
    async def list_tools(self) -> list[RawTool]: ...
    async def call_tool(self, name: str, args: dict[str, Any]) -> RawResult: ...
    async def close(self) -> None: ...
```

`mcp/hooks.py` (D11):
```python
class ConnectionDenied(Exception): ...

class ConnectionPolicy(Protocol):
    async def before_connect(self, config: McpServerConfig) -> dict[str, str]: ...  # extra HTTP headers; raise ConnectionDenied to block

class ToolFilter(Protocol):
    def admit(self, server: str, tool: RawTool) -> bool: ...

class AllowAll:   # default for both: before_connect returns {}, admit returns True
```

`mcp/config.py`: frozen dataclass `McpServerConfig(name, transport, url, command, args, env, timeout, tools)` and `load_servers(path: str) -> list[McpServerConfig]`. Follow D8:
- Empty path returns `[]`. A missing or unreadable file or bad JSON logs an error and returns `[]`. The top level must be a JSON list, otherwise log an error and return `[]`.
- Validate each entry on its own. A bad entry logs an error with the entry index and name, and is skipped. Good entries survive (E6).
- `name`: required, must match `[a-zA-Z0-9_-]{1,64}` (the hub `TOOL_NAME` at `hub/hub.py:18`, D13), no `__` (`SEP`, `hub/types.py:9`), unique. A duplicate is skipped.
- `transport` in `http`, `sse`, `stdio`. `url` required for `http` and `sse`, scheme `http` or `https`, no user info, no query string. `command` (str) and `args` (list of str) required for `stdio`. `env` (dict str to str) is allowed for `stdio` only: an `env` key on an `http` or `sse` entry rejects that entry.
- `timeout`: float, default 10, bounds 1 to 60 inclusive.
- `tools`: list of str, required. A name that fails D13 is dropped with a logged error.
- Use only stdlib validation or a small pydantic model per entry. Do not read secrets from the file (T8).

`server/src/ota_server/config.py`: add to `Settings` (after `history_turns`, line 30) the field `mcp_servers_file: str = ""` with a comment. Env name is `OTA_MCP_SERVERS_FILE` through the existing prefix (line 15).

Tests in `server/tests/test_mcp_config.py`. Write files with `tmp_path`. Check logs with `caplog`. The Settings scenario uses `monkeypatch.setenv` and builds `Settings` with the required fields.

## Acceptance Criteria
```gherkin
Scenario Outline: Valid entries load
  Given a file with one <transport> entry with name "n8n", timeout 5 and tools ["a"]
  When load_servers reads the file
  Then it returns 1 McpServerConfig with the same name, transport, timeout and tools
  Examples:
    | transport |
    | http      |
    | sse       |
    | stdio     |

Scenario: No file configured
  Given the path is an empty string
  When load_servers runs
  Then it returns an empty list

Scenario: Bad JSON
  Given a file that holds "{not json"
  When load_servers runs
  Then it returns an empty list
  And an error is logged

Scenario Outline: Bad entry is skipped, good entry survives
  Given a file with one good entry and one entry with <defect>
  When load_servers runs
  Then it returns only the good entry
  And an error is logged for the bad entry
  Examples:
    | defect                                  |
    | a duplicate name                        |
    | name "bad name!"                        |
    | name "a__b"                             |
    | url "https://user:pw@host/mcp"         |
    | url "https://host/mcp?token=x"         |
    | timeout 0.5                             |
    | timeout 61                              |
    | transport "ws"                          |
    | stdio entry with no command             |

Scenario Outline: env is for stdio only
  Given an entry with transport <transport> and env {"FOO": "bar"}
  When load_servers runs
  Then <result>
  Examples:
    | transport | result                                        |
    | http      | the entry is skipped and an error is logged   |
    | sse       | the entry is skipped and an error is logged   |
    | stdio     | the entry loads with env {"FOO": "bar"}       |

Scenario: Allowlist name that fails D13
  Given an entry whose tools are ["ok", "bad name"]
  When load_servers runs
  Then the entry loads with tools ["ok"]
  And an error is logged for "bad name"

Scenario: Default hooks
  Given the default ConnectionPolicy and ToolFilter
  When before_connect runs and admit runs for any tool
  Then before_connect returns {} and admit returns True

Scenario: Settings field
  Given the env variable OTA_MCP_SERVERS_FILE is "/x/servers.json"
  When Settings loads
  Then settings.mcp_servers_file is "/x/servers.json"
  And without the variable it is ""
```
