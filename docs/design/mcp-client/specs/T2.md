# T2: McpSource: allowlist, naming, result mapping, timeout and cancel policy

## Context
`McpSource` is the `ToolSource` (`hub/types.py:51-59`) for one external server. It holds all policy and no SDK code (D5). It serves B2, T4, T5, E2 to E5, F1, F5, M2, D5, D5a and D6. The hub already truncates results in `wrap()` and guards each call at `source.timeout + GUARD_GRACE` (`hub/hub.py:87`), so this source must not truncate and must time out first.

## Technical Approach
Create `server/src/ota_server/mcp/source.py`. Import only `port.py`, `hooks.py`, `config.py` (T1) and `hub.types`. No SDK import.

`McpSource(config: McpServerConfig, conn: McpConnection, tools: list[RawTool], tool_filter: ToolFilter = AllowAll())` with `name = config.name` and `timeout = config.timeout`. `specs()` stays sync. The classmethod `async McpSource.build(config, conn, tool_filter=AllowAll()) -> McpSource` calls `conn.list_tools()` and then constructs the source. T5 calls `McpSource.build`.

Spec building (once, at construction):
- Keep a tool only if its name is in `config.tools` (E2: unlisted tools hidden) and `tool_filter.admit(config.name, tool)` is true.
- Each allowlist name that the server did not list logs a warning (E3) and is ignored.
- Full name is `<server>__<tool>` through `ToolSpec.full_name` (`hub/types.py:46`). A tool whose full name fails `TOOL_NAME` (`hub/hub.py:18`) is dropped with a logged error. The hub raises `ValueError` otherwise (`hub/hub.py:27`).
- `ToolSpec(source=config.name, name=tool.name, description=tool.description, schema=tool.schema)`.

`call(tool, args)`:
- A tool not in the kept set returns `ToolOutcome(False, "unknown tool", "unknown_tool")` and does not touch the connection.
- Run `conn.call_tool` under one `asyncio.timeout(self.timeout)` (D6). The reconnect and retry that T4 adds in the connection is inside this deadline. On `TimeoutError` return `ToolOutcome(False, "the <name> did not answer in time", "tool_timeout")`. Do not reconnect.
- Catch `Exception` only. Log it with `log.exception` and return `ToolOutcome(False, "tool failed", "mcp_error")` (F5). Never put the exception text in the outcome. `asyncio.CancelledError` is a `BaseException` and must be re-raised (D5a). Do not add `except BaseException`.
- Result mapping: `is_error` true returns `ToolOutcome(False, "the tool reported an error", "tool_error")` with no raw body (E4). Otherwise join parts with `\n`: text parts as is, `image` as `[image]`, `resource` as `[resource]` (E5). No truncation.

Tests in `server/tests/test_mcp_source.py` over a `FakeConnection` defined in that file (implements `McpConnection`, no SDK). Give it controllable delay, raise and result.

## Acceptance Criteria
```gherkin
Scenario: Unlisted tool is hidden
  Given a FakeConnection that lists tools "a" and "b" and an allowlist ["a"]
  When McpSource.build runs
  Then specs() holds only "a" with full_name "<server>__a"
  And a call to "b" returns code "unknown_tool" and the connection got 0 calls

Scenario: Allowlist name missing on the server
  Given an allowlist ["a", "gone"] and a server that lists only "a"
  When McpSource.build runs
  Then a warning naming "gone" is logged
  And specs() holds "a"

Scenario: Bad full name is dropped
  Given the server lists a tool "bad name" that is in the allowlist
  When McpSource.build runs
  Then specs() does not hold it
  And an error is logged

Scenario: Tool filter hides a tool
  Given a ToolFilter whose admit returns False for "a"
  When McpSource.build runs
  Then specs() does not hold "a"

Scenario: isError gives a generic text
  Given the connection returns RawResult(is_error=True) with the body "secret stack trace"
  When call runs
  Then the outcome has ok False
  And the outcome text does not contain "secret stack trace"

Scenario: Non-text parts become placeholders
  Given the connection returns parts text "hi", image and resource
  When call runs
  Then the outcome has ok True and text "hi\n[image]\n[resource]"

Scenario: Timeout
  Given a source with timeout 1 and a connection that sleeps 5 s
  When call runs
  Then it returns ok False with code "tool_timeout" within 1.5 s
  And a following call on a fast connection returns ok True

Scenario: Any exception becomes an outcome
  Given a connection that raises RuntimeError("boom")
  When call runs
  Then the outcome has ok False and the text does not contain "boom"

Scenario: Caller cancel is re-raised
  Given a call that is waiting on a slow connection
  When the caller task is cancelled
  Then the task ends cancelled with CancelledError
```
