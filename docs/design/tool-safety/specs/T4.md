# T4: NoRedirectTransport and guarded client in adapters

## Context
The mcp SDK 1.30.0 follows same-origin redirects and ignores `follow_redirects`, so a vetted host can redirect the client to an internal address. This task blocks every 3xx on `http` and `sse`. It serves T8, D6 and M3.

## Technical Approach
Edit `server/src/ota_server/mcp/adapters.py`.

```python
class RedirectBlocked(Exception): ...   # not an httpx.TransportError, so is_transport_error is False

class NoRedirectTransport(httpx.AsyncBaseTransport):
    def __init__(self, inner: httpx.AsyncBaseTransport) -> None: ...
    async def handle_async_request(self, request: httpx.Request) -> httpx.Response: ...  # 3xx: aclose response, raise RedirectBlocked
    async def aclose(self) -> None: ...   # closes inner

def guarded_client(
    headers: dict[str, str] | None = None,
    timeout: httpx.Timeout | None = None,
    auth: httpx.Auth | None = None,
) -> httpx.AsyncClient: ...
```

`guarded_client` returns `httpx.AsyncClient(transport=NoRedirectTransport(httpx.AsyncHTTPTransport()), follow_redirects=False, headers=headers, timeout=timeout or <the SDK default>, auth=auth)`. Its signature must match `McpHttpClientFactory` of the SDK, so `sse_client(url, headers=headers, httpx_client_factory=guarded_client)` accepts it. Resolved: use `httpx.Timeout(MCP_DEFAULT_TIMEOUT, read=MCP_DEFAULT_SSE_READ_TIMEOUT)` (30 s, 300 s), imported from `mcp.shared._httpx_utils`, where both names are in `__all__` of mcp 1.30.0.

Change `_http_transport` to use `guarded_client(headers=headers)` in place of `create_mcp_http_client`, and remove that import if it is unused. The `sse` branch of `sdk_transport` passes `httpx_client_factory=guarded_client`.

Fail fast: a connect to a server that answers 307 must fail in under 2 s, not by the 5 s `RECONNECT_TIMEOUT`. If the SDK swallows `RedirectBlocked` in its reader task, the connect hangs. Then add a flag on the transport (for example `blocked: bool`) that the owner task checks, and raise `RedirectBlocked` from `_own`. Cover this with the timed test. A redirect on a mid-session call returns an error outcome (`McpSource` already maps any `Exception` to `mcp_error`) and the session survives. A reconnect may happen and fails again on the same redirect.

Fakes: add to `server/tests/mcp_fakes.py` a tiny HTTP server on 127.0.0.1 (stdlib `asyncio.start_server` or the existing fake style) that answers a same-origin 307 `Location` for every request, and one that answers normally and then 307 after N requests. Tests in `server/tests/test_mcp_adapters.py` use a policy that returns `{}`.

## Acceptance Criteria
```gherkin
Scenario Outline: Redirect on connect fails fast
  Given a fake server on 127.0.0.1 that answers a same-origin 307 to every request
  When SdkConnection.open runs for a <transport> entry
  Then it raises an error
  And it takes less than 2 seconds
  Examples:
    | transport |
    | http      |
    | sse       |

Scenario: Redirect on a mid-session call
  Given a connected http session and a fake server that now answers 307
  When McpSource.call runs
  Then the outcome is not ok with code "mcp_error"
  And the next call on a recovered server still works, or fails with an error outcome, without a crash

Scenario: RedirectBlocked is not a transport error
  Given a RedirectBlocked instance
  When is_transport_error runs
  Then it returns False

Scenario: Timeout and headers reach the client
  Given guarded_client called with headers {"X-A": "1"} and a timeout of 3 seconds
  When the client is inspected
  Then client.headers holds "X-A" with "1"
  And client.timeout equals httpx.Timeout(3)
  And client.follow_redirects is False

Scenario: Existing adapter behavior
  Given the existing adapter and reconnect tests
  When "cd server && pytest tests/test_mcp_adapters.py" runs
  Then they all pass
```
