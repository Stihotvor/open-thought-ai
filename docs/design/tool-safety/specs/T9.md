# T9: Integration tests for redirect block and secret header, and gate

## Context
Unit tests cover each part. This task proves the parts work together over a real local HTTP path, and runs the full quality gate. It serves M3, M4, M6, F1, T12 and T13.

## Technical Approach
Create `server/tests/test_mcp_tool_safety.py`. Reuse the fake servers in `server/tests/mcp_fakes.py` (extended in T4). The fake servers listen on 127.0.0.1. Put `127.0.0.1` in the allowlist of a `SafeConnectionPolicy` and use `http` URLs. Build configs with the tools map form and pins from `tool_hash`.

Tests:
- Redirect: a fake http server answers 307 to every request. The test opens the connection through `SdkConnection.open` with the real `SafeConnectionPolicy` and measures the time with `time.monotonic`. It must fail in under 2 s.
- Secret header: `monkeypatch.setenv("MCP_SECRET_TEST", "tok-12345")`, config `headers={"Authorization": "MCP_SECRET_TEST"}`, with the policy `environ` set to `os.environ`. The fake server records the request headers. Assert the recorded `Authorization` equals the value and that `caplog.text` (at DEBUG, root logger) has no `tok-12345`.
- Denied server: a config for a host that resolves (fake resolver) to `10.0.0.9`, and one good fake server. Start through `McpRegistry.start` (or the lifespan helper that T7 wires). The startup does not raise, the good server's tool works, and device tools still work through `McpHub` (F1).

Gate: run `server/scripts/gate.sh` and fix any ruff, mypy or coverage gap that the new code in T1 to T7 left (coverage >= 90 %). Do not change code outside `server/tests/` except for a defect that a test finds. Report such a defect as `OPEN:` and do not hide it.

## Acceptance Criteria
```gherkin
Scenario: Redirect fails the connect (M3)
  Given a fake http server on 127.0.0.1 that answers 307 and 127.0.0.1 on the allowlist
  When SdkConnection.open runs with the real policy
  Then it raises an error
  And it takes less than 2 seconds

Scenario: Secret header reaches the server and not the logs (M4)
  Given the env variable MCP_SECRET_TEST is "tok-12345" and a header mapped to it
  When the client connects to the fake http server and calls a tool
  Then the fake server saw the header value "tok-12345"
  And caplog holds 0 occurrences of "tok-12345"

Scenario: Denied server does not stop startup (F1)
  Given one server that the policy denies and one good server
  When the registry starts
  Then startup does not raise
  And the good server's tool call returns an ok outcome
  And a device tool call still works

Scenario: Quality gate (M6)
  Given all tasks T1 to T8 are done
  When "server/scripts/gate.sh" runs
  Then ruff reports 0 findings and mypy reports 0 errors
  And all tests pass
  And coverage is at least 90 %
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
