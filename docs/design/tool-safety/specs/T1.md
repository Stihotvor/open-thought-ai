# T1: ssrf.check_host with injectable resolver

## Context
External MCP servers must not make the server call internal hosts (B2). This task builds the pure SSRF check that T5 uses. It serves T6, T7, E1, E2, E5, E7, D1 and M1.

## Technical Approach
Create `server/src/ota_server/mcp/ssrf.py`. Use stdlib only (`ipaddress`, `asyncio`). Do not import the `mcp` SDK.

```python
Resolver = Callable[[str], Awaitable[list[str]]]   # host -> list of IP strings

async def default_resolver(host: str) -> list[str]: ...   # loop.getaddrinfo, unique sockaddr[0]

async def check_host(
    host: str, allowed_hosts: frozenset[str], resolver: Resolver = default_resolver
) -> str | None: ...   # None = allowed; otherwise the deny reason (short text, no secrets)
```

Rules (D1), in this order:
1. Lowercase the host. If it is in `allowed_hosts` (the set is already lowercase), return `None` (E2).
2. Try `ipaddress.ip_address(host)` first. If it parses, it is the only IP to check. Skip the single-label rule (so `2001:db8::1` is not single-label).
3. If it does not parse and the name has no `.`, return reason `single-label host`.
4. Otherwise call `resolver(host)`. A resolver exception or an empty list returns reason `dns failure` (E7).
5. For each IP: if it is IPv6 with `ipv4_mapped`, replace it with the IPv4 address (E5). Deny if `is_loopback`, `is_link_local`, `is_private`, `is_unspecified` or `is_multicast`. Check every IP, one bad IP denies the host (E1). Reason names the range class, e.g. `blocked address (private)`.

`is_private` covers 10/8, 172.16/12, 192.168/16 and fc00::/7. Add a test that asserts each range (do not rely on the doc).

The function returns a reason and does not raise or log. T5 logs the denial.

Tests in `server/tests/test_mcp_ssrf.py` use `pytest.mark.asyncio` as in the other mcp tests and a fake resolver `async def fake(host)` that reads a dict.

## Acceptance Criteria
```gherkin
Scenario Outline: Blocked address ranges
  Given a fake resolver that maps "svc.example.com" to <ip>
  When check_host runs for "svc.example.com" with an empty allowlist
  Then it returns a non-empty reason
  Examples:
    | ip                |
    | 127.0.0.1         |
    | 169.254.169.254   |
    | 10.1.2.3          |
    | 172.16.0.5        |
    | 192.168.1.1       |
    | fc00::1           |
    | 0.0.0.0           |
    | 224.0.0.1         |

Scenario: Single-label name
  Given a host "n8n" and an empty allowlist
  When check_host runs
  Then it returns a non-empty reason
  And the resolver is not called

Scenario: IPv6 literal is not single-label
  Given a host "2001:db8::1" and an empty allowlist
  When check_host runs
  Then it returns a reason only if the IP is blocked, and the reason is not "single-label host"

Scenario: IPv4-mapped IPv6 (E5)
  Given a resolver that maps "a.example.com" to "::ffff:10.0.0.1"
  When check_host runs
  Then it returns a non-empty reason

Scenario: Mixed public and private IPs (E1)
  Given a resolver that maps "a.example.com" to ["93.184.216.34", "10.0.0.9"]
  When check_host runs
  Then it returns a non-empty reason

Scenario: Public host
  Given a resolver that maps "a.example.com" to ["93.184.216.34"]
  When check_host runs
  Then it returns None

Scenario: Allowlist bypass is case-insensitive (E2)
  Given the allowlist {"n8n"} and a host "N8N"
  When check_host runs
  Then it returns None
  And the resolver is not called

Scenario: Resolver error (E7)
  Given a resolver that raises OSError
  When check_host runs for "a.example.com"
  Then it returns a non-empty reason
```
