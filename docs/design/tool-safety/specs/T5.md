# T5: SafeConnectionPolicy (scheme rule, SSRF, secret headers)

## Context
The policy seam `ConnectionPolicy.before_connect` is empty. This task fills it so an external server cannot reach internal hosts and secrets come from the environment only (B2, B3). It serves T5, T6, T9, T12, E7, F1, F2 and D2.

## Technical Approach
Create `server/src/ota_server/mcp/policy.py`. It imports `check_host` from T1, `ConnectionDenied` from `mcp/hooks.py` and `McpServerConfig` from `mcp/config.py`.

```python
class SafeConnectionPolicy:
    def __init__(
        self,
        allowed_hosts: frozenset[str],
        resolver: Resolver = default_resolver,
        environ: Mapping[str, str] | None = None,   # None = os.environ
    ) -> None: ...
    async def before_connect(self, config: McpServerConfig) -> dict[str, str]: ...
```

`before_connect` (D2):
1. `stdio`: return `{}`.
2. Parse `urlsplit(config.url)`; host is `parts.hostname` lowercase.
3. Scheme rule (T5): `https` passes. `http` passes only when the host is loopback (an IP literal with `is_loopback`) or in `allowed_hosts`. Otherwise deny with reason `http needs https`.
4. `reason = await check_host(host, allowed_hosts, resolver)`. A reason denies.
5. For each `(header, var)` in `config.headers`: `environ[var]` missing or empty denies with reason `missing variable <var>` (name only). Build and return `{header: value}`.
6. Every denial logs one WARNING `mcp %s: connection denied (host %s): %s` with the server, the host and the reason, then raises `ConnectionDenied(reason)`. Never log a header value (T12).

The policy keeps no state, so each connect and each reconnect re-runs the check (F2). `SdkConnection._own` already calls it each time and `McpSource.call` maps the failure to an error outcome.

Resolved (lead, no design change): loopback means an IP literal in 127.0.0.0/8 or ::1 only. `localhost` needs an allowlist entry, as every single-label name does.

Tests in `server/tests/test_mcp_policy.py` with a fake resolver, a fake `environ` dict and `caplog`.

## Acceptance Criteria
```gherkin
Scenario: https to a public host
  Given an https entry for "a.example.com" that resolves to a public IP
  When before_connect runs
  Then it returns {} without an error

Scenario: http to a public host
  Given an http-scheme url for "a.example.com" that resolves to a public IP
  When before_connect runs
  Then it raises ConnectionDenied

Scenario Outline: http to an allowlisted loopback or allowlisted host
  Given an http-scheme url with host <host> and the allowlist {"n8n", "127.0.0.1"}
  When before_connect runs
  Then it does not raise
  Examples:
    | host      |
    | 127.0.0.1 |
    | n8n       |

Scenario: http to loopback that is not allowlisted
  Given an http-scheme url with host 127.0.0.1 and the allowlist {"n8n"}
  When before_connect runs
  Then it raises ConnectionDenied

Scenario: Blocked IP
  Given an https entry whose host resolves to 10.0.0.9
  When before_connect runs
  Then it raises ConnectionDenied
  And a WARNING log holds the server name, the host and a reason

Scenario: Secret header from the environment (T9)
  Given headers {"X-Api": "MCP_SECRET_N8N"} and environ {"MCP_SECRET_N8N": "s3cr3t"}
  When before_connect runs
  Then it returns {"X-Api": "s3cr3t"}
  And no log record contains "s3cr3t"

Scenario: Missing variable (T9)
  Given headers {"X-Api": "MCP_SECRET_N8N"} and an empty environ
  When before_connect runs
  Then it raises ConnectionDenied
  And a log record names "MCP_SECRET_N8N"

Scenario: stdio entry
  Given a stdio entry
  When before_connect runs
  Then it returns {}
  And the resolver is not called

Scenario: Re-check on reconnect (F2)
  Given a host that resolved to a public IP on the first call
  When the fake resolver now returns 10.0.0.9 and before_connect runs again
  Then it raises ConnectionDenied

Scenario: DNS failure (E7)
  Given a resolver that raises OSError
  When before_connect runs
  Then it raises ConnectionDenied
  And a WARNING log is written
```
