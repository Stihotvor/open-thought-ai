# T3: HashToolFilter and per-tool try in McpSource

## Context
A changed or hostile server must not change what the LLM sees without owner approval (B1). This task adds the hash pin check and the size caps. It serves T3, T4, E3, E4, F3, F4, D3, D4 and M2.

## Technical Approach
Create `server/src/ota_server/mcp/toolfilter.py`. It imports `RawTool` from `mcp/port.py` and nothing from the SDK.

```python
MAX_DESCRIPTION = 1000
MAX_SCHEMA = 4000

def canonical(tool: RawTool) -> str: ...   # json.dumps of {"name","description","input_schema"}, sort_keys=True, separators=(",", ":"), ensure_ascii=False
def schema_json(tool: RawTool) -> str: ... # same dumps, of tool.schema only
def tool_hash(tool: RawTool) -> str: ...   # "sha256:" + sha256(canonical(tool).encode()).hexdigest()

class HashToolFilter:
    def __init__(self, pins: Mapping[str, Mapping[str, str]]) -> None: ...  # server -> tool -> pin
    def admit(self, server: str, tool: RawTool) -> bool: ...
```

`tool_hash` uses the bare tool name (`tool.name`) and `tool.schema` as `input_schema` (D3). Resolved (lead): `ensure_ascii=False`, UTF-8 bytes into SHA-256. The owner copies the hash from the WARNING log and never computes it by hand.

`admit` order (D3):
1. `len(tool.description) > MAX_DESCRIPTION` or `len(schema_json(tool)) > MAX_SCHEMA`: log ERROR with server and tool, return False (T4).
2. Look up `pins.get(server, {}).get(tool.name)`. If it equals `tool_hash(tool)`, return True.
3. Otherwise log WARNING `mcp %s: tool %r not admitted, current hash %s` with the server, tool name and current hash, return False (T3, E4). Never log the description.

`server/src/ota_server/mcp/source.py`: in `_build_specs` replace `tool_filter.admit(...)` with a helper `_admitted(config, tool, tool_filter) -> bool` that wraps the call in `try/except Exception`, logs `log.error` with the server, tool name and exception type (not the message) and returns False (F4, D4). The keys of `config.tools` stay the allowlist, and the E3 warning stays. `McpSource.call` already returns `unknown tool` for a tool outside `_kept` (F3).

Tests: new `server/tests/test_mcp_toolfilter.py` (hash, caps, log content) and additions to `server/tests/test_mcp_source.py` (raising filter, unadmitted call). Use a small `RawTool` fixture with a fixed expected hash string for the stability test.

## Acceptance Criteria
```gherkin
Scenario: Matching pin is admitted
  Given a pin equal to tool_hash(tool) for server "s" and tool "t"
  When admit("s", tool) runs
  Then it returns True

Scenario: Missing pin is not admitted
  Given a filter with no pin for tool "t"
  When admit runs
  Then it returns False
  And a WARNING log holds "t" and the value of tool_hash(tool)

Scenario: Changed description is not admitted (E4)
  Given a pin for the old description
  When admit runs with a changed description
  Then it returns False
  And a WARNING log holds the new hash

Scenario: Description over 1 000 characters
  Given a tool with a description of 1 001 characters and a matching pin
  When admit runs
  Then it returns False
  And an ERROR log is written

Scenario: Description of exactly 1 000 characters
  Given a tool with a description of 1 000 characters and a matching pin
  When admit runs
  Then it returns True

Scenario: Schema over 4 000 characters
  Given a tool whose canonical schema JSON is longer than 4 000 characters and a matching pin
  When admit runs
  Then it returns False
  And an ERROR log is written

Scenario: Stable hash
  Given a fixed RawTool fixture
  When tool_hash runs twice, with the schema keys in another order the second time
  Then both results equal one fixed "sha256:..." string

Scenario: Filter raises (F4)
  Given a McpSource with two allowlisted tools and a filter that raises for the first
  When the source is built
  Then specs() holds only the second tool
  And an error is logged
  And McpHub.run for the second tool does not raise

Scenario: Unadmitted tool call (F3)
  Given a tool the filter did not admit
  When McpSource.call runs for it
  Then the outcome is not ok with code "unknown_tool"
```
