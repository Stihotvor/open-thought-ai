# T6: McpHub keep-first for source and tool names

## Context
Two sources with one name, or two tools with one full name, make a tool call ambiguous. A hostile or wrong servers file must not shadow the device tools or crash startup. This task makes the hub keep the first and log an error for the later one. It serves T2, F1 and D7.

## Technical Approach
Edit `McpHub.__init__` in `server/src/ota_server/hub/hub.py` (read the current code first, and keep its public behavior for valid input).

- Source name: keep the first source for a name. For a later source with the same name, `log.error` with the name and skip the source with all its specs.
- A source whose `name` contains `SEP` (`__`, from `hub/types.py`) is skipped whole with `log.error`.
- Spec full name: keep the first spec for a full name. `log.error` for each later one and skip it.
- A spec whose full name fails `TOOL_NAME` is logged and skipped, not raised (replaces a raise, if the hub raises now).

The device source is passed first by `main.py`, so it wins over a later source named `device`. No error text may carry tool descriptions.

Tests in `server/tests/test_hub.py` use small fake `ToolSource` classes. Use `caplog` for the log checks.

## Acceptance Criteria
```gherkin
Scenario: Duplicate source name
  Given two sources named "a", the first with tool "x" and the second with tools "y" and "z"
  When McpHub is built
  Then the hub holds only "a__x"
  And an ERROR is logged for the second source

Scenario: Source name with "__"
  Given a source named "a__b" with one tool
  When McpHub is built
  Then the hub holds none of its tools
  And an ERROR is logged

Scenario: Duplicate full name
  Given one source with two specs of the same name "x"
  When McpHub is built
  Then the hub holds one "x" and it is the first spec
  And an ERROR is logged for the second

Scenario: Bad spec name
  Given a source with one spec whose full name fails the format check and one valid spec
  When McpHub is built
  Then no exception is raised
  And only the valid spec is held
  And the bad name is logged

Scenario: Valid input unchanged
  Given the existing hub tests
  When "cd server && pytest tests/test_hub.py" runs
  Then they all pass
```
