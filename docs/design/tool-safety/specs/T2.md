# T2: Config validators and migration of #28 tests to the tools map

## Context
A servers file must not hold literal secrets, reserved names or a stdio env that leaks secrets (B1, B2). This task changes the config shape and its validators. It serves T2, T3, T9, T10, E6, D5 and M5. Later tasks (T3, T4, T5, T8) read the new fields.

## Technical Approach
In `server/src/ota_server/mcp/config.py` keep the frozen dataclass `McpServerConfig` and change two fields:
- `tools: dict[str, str]` (tool name to `sha256:<64 hex>`, default empty dict).
- `headers: dict[str, str]` (header name to `MCP_SECRET_*` variable name, default empty dict).

Add constants `PIN = re.compile(r"sha256:[0-9a-f]{64}")`, `SECRET_VAR = re.compile(r"MCP_SECRET_[A-Z0-9_]+")`, `SECRET_ENV_WORDS = ("KEY", "TOKEN", "SECRET", "PASSWORD", "AUTH")` and `RESERVED_NAMES = frozenset({"device"})`.

Validators inside `_parse_entry` (each raises `ValueError`, the existing `_try_entry` logs it and skips the entry):
- `_check_name`: add a reject for a name in `RESERVED_NAMES` (T2).
- `_check_tools(server, tools)`: must be a dict. A list gives `ValueError("tools must be a map of tool name to sha256 pin")`. Each value must fullmatch `PIN`, else reject the entry. A key that fails `TOOL_NAME` is dropped with a logged error (as in #28). Return `dict[str, str]`.
- `_check_headers(entry)`: absent gives `{}`. For `stdio` any `headers` key rejects the entry (E6). For `http` and `sse` it must be `dict[str, str]` and each value must fullmatch `SECRET_VAR` (T9). The error message names the header name, never prints the literal value.
- `_check_stdio` env: reject a key whose uppercase form contains any of `SECRET_ENV_WORDS`, or a value that starts with `MCP_SECRET_` (T10). The message names the key only.
- `load_servers`: after the per-entry loop, one cross-entry pass. Track `MCP_SECRET_*` names used per accepted entry. An entry that uses a name already used by an earlier accepted entry is rejected with a logged error (T9). Do it inside the loop with a `used: dict[str, str]` map passed to `_try_entry`, so the first entry wins.

Migrate the #28 tests to the tools map form: `server/tests/test_mcp_config.py`, `test_mcp_source.py`, `test_mcp_adapters.py`, `test_mcp_registry.py`, `test_mcp_e2e.py`. A fixture value is `"sha256:" + "0" * 64` unless the test needs the real hash. Where a test builds `McpServerConfig(tools=[...])`, change it to a dict. Source tests that need a filter keep `ALLOW_ALL` until T3.

Add the new config scenarios to `test_mcp_config.py`. Use `tmp_path` and `caplog`.

## Acceptance Criteria
```gherkin
Scenario: Valid https entry with headers and tools map
  Given an https entry with tools {"a": "sha256:<64 hex>"} and headers {"X-Api": "MCP_SECRET_N8N"}
  When load_servers runs
  Then it returns 1 McpServerConfig with the same tools and headers

Scenario Outline: Entry is rejected and an error is logged
  Given a file with one good entry and one entry with <defect>
  When load_servers runs
  Then it returns only the good entry
  And an error is logged for the bad entry
  Examples:
    | defect                                                       |
    | name "device"                                                |
    | a header value "plain-secret"                                |
    | the same MCP_SECRET_X name in two entries (second is skipped) |
    | a stdio env key "API_KEY"                                    |
    | a stdio env value "MCP_SECRET_X"                             |
    | headers on a stdio entry                                     |
    | tools as a list ["a"]                                        |
    | a pin "sha256:abc"                                           |

Scenario: Error log never holds a literal header value
  Given an entry with a header value "plain-secret"
  When load_servers runs
  Then no log record contains "plain-secret"

Scenario: Bad tool name key is dropped
  Given an entry with tools {"ok": <pin>, "bad name": <pin>}
  When load_servers runs
  Then the entry loads with tools {"ok": <pin>}
  And an error is logged for "bad name"

Scenario: Migrated #28 tests
  Given test_mcp_config, test_mcp_source, test_mcp_adapters, test_mcp_registry and test_mcp_e2e use the tools map form
  When "cd server && pytest" runs
  Then all of them pass
```
