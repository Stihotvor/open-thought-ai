# Decision — tool safety (issue #31)

## Context
#28 (PR #64) built the external MCP client with two empty seams in `server/src/ota_server/mcp/hooks.py`: `ConnectionPolicy.before_connect` and `ToolFilter.admit`. The `main.py` lifespan passes the default `ALLOW_ALL`. This issue fills the seams and closes the four security items from the #28 review. Rules: `docs/security.md:34-41,49`. Requirements: `requirements.md`. The cap of 4 tool calls per turn exists already and does not change.

A fact from the review of the paths: mcp SDK 1.30.0 follows same-origin redirects itself (`stream_within_origin` in `mcp/shared/_httpx_utils.py`). It ignores the client `follow_redirects` setting. So every path needs an httpx transport wrapper that raises on any 3xx.

## Options
- Path 1: concrete classes on the existing seams, config validators, a 3xx guard. Feasible with changes. Reviewer preference.
- Path 2: a load-time pipeline into a new `ValidatedServer` type. Feasible, higher cost: it changes the config shape in all modules and #28 tests.
- Path 3: a network-layer guard with an httpcore backend that connects only to the vetted IP. Feasible with changes. It closes DNS rebinding, which T6 does not require, with semi-public httpcore API.
- Path 4: hub admission for all sources. Feasible with changes, not recommended: pins leak into the `ToolSource` protocol, and a server with 0 admitted tools stays open.

## Decision
The owner chose Path 1 with the 3xx guard from Path 3 (G1, 2026-11-20).
- D1: New `mcp/ssrf.py`: `check_host(host, allowed_hosts, resolver)`. It uses stdlib `ipaddress` and blocks the T6 ranges, unwraps IPv4-mapped IPv6 (E5), parses an IP literal with `ipaddress` first and applies the single-label rule to DNS names only (so `2001:db8::1` is not single-label), and checks every resolved IP (E1). An exact host match on the allowlist (case-insensitive, E2) skips the check. `Resolver` is a callable type. The default uses `loop.getaddrinfo`. Tests inject a fake resolver (T13). A resolver error is a deny (E7).
- D2: New `mcp/policy.py`: `SafeConnectionPolicy(allowed_hosts, resolver, environ)` implements `ConnectionPolicy`. `environ` is the process environment merged over `.env` (process variables win), because `Settings` also reads `.env`. For `http` and `sse` it checks the T5 scheme rule, runs `check_host`, then reads each `MCP_SECRET_*` variable from `environ` and returns the headers (T9). A missing variable raises `ConnectionDenied`. The policy itself logs every denial at WARNING with the server, the host and the reason (scheme, blocked range, single-label, DNS failure, missing variable name), never a secret value (T12, E7). For `stdio` it returns `{}`. It runs on each connect and reconnect, because `SdkConnection` calls it there (F2).
- D3: New `mcp/toolfilter.py`: `tool_hash(tool)` is `"sha256:" + hex` of SHA-256 over the canonical JSON (`sort_keys=True`, `separators=(",", ":")`) of `{"name", "description", "input_schema"}` with the bare tool name. `HashToolFilter(pins: Mapping[str, Mapping[str, str]])`, where `main.py` builds `pins` only from `config.tools` (one source of truth), implements `ToolFilter.admit`. It checks the caps first (description > 1 000 chars, canonical schema > 4 000 chars: ERROR log, not admitted, T4). Then it compares the pin. A missing or different pin: WARNING log with the server, tool and current hash, not admitted (T3, E4).
- D4: `McpSource._build_specs` calls `admit` inside a per-tool `try/except Exception`. An exception logs an error and does not admit that tool (F4). The keys of `config.tools` stay the allowlist (E3 unchanged).
- D5: `mcp/config.py` keeps the `McpServerConfig` class. Field changes: `tools` changes from `list[str]` to `dict[str, str]`, and a new field `headers: dict[str, str]` (default empty). Validators:
  - `tools`: tool name to `sha256:<64 hex>`. The old list form rejects the entry. A pin value with a bad format rejects the entry. A tool name key that fails `TOOL_NAME` is dropped with a logged error, as in #28.
  - `name`: `device` is reserved (T2).
  - `headers`: `dict[str, str]`, `http` and `sse` only (E6). Each value must match `MCP_SECRET_[A-Z0-9_]+` (T9).
  - `env` for `stdio`: a key that contains `KEY`, `TOKEN`, `SECRET`, `PASSWORD` or `AUTH` (case-insensitive), or a value that starts with `MCP_SECRET_`, rejects the entry (T10).
  - `load_servers` does one cross-entry pass: an `MCP_SECRET_*` name used in a second entry rejects that entry (T9, bound to one host).
  The URL check keeps `http` and `https` at load time. The host rule (T5) lives only in the policy, so the allowlist is in one place.
- D6: New `NoRedirectTransport(httpx.AsyncBaseTransport)` in `adapters.py`. It wraps `httpx.AsyncHTTPTransport`. On a 3xx response it closes the response and raises `RedirectBlocked`. `RedirectBlocked` is not an `httpx.TransportError` (T8). `create_mcp_http_client` takes no `transport` argument, so a local factory `guarded_client(headers, timeout, auth)` builds `httpx.AsyncClient(transport=NoRedirectTransport(httpx.AsyncHTTPTransport()), follow_redirects=False)` and uses the passed `timeout` (the SDK default when it is None) and passes `auth` and `headers` through. `_http_transport` uses it, and `sse_client` gets it as `httpx_client_factory`. The redirect must fail fast: a connect to a server that answers 307 fails in under 2 s, not by the 5 s connect deadline. If the SDK swallows the exception inside its reader task, the adapter must surface it (for example by a flag the transport sets and the owner task checks). A redirect on a mid-session call returns an error outcome. A reconnect is allowed, and it fails again on the same redirect.
- D7: `hub/hub.py`: `McpHub.__init__` keeps the first source for a source name and logs an ERROR for a later source with that name, which is skipped with all its specs. A source whose name has `__` is skipped whole. It keeps the first spec for a full name and logs an ERROR for each later one. A spec name that fails the format check is logged and skipped, not raised (T2, F1).
- D8: `Settings.mcp_allowed_hosts: str` (env `OTA_MCP_ALLOWED_HOSTS`, comma-separated, default empty). A property `allowed_hosts` returns a lowercase frozenset with blanks stripped (T7). A plain `str` field avoids the pydantic-settings JSON decode of collection fields. The `main.py` lifespan builds `SafeConnectionPolicy` and `HashToolFilter` from `Settings` and the loaded configs and passes them to `McpRegistry.start` (T11).
- D9: Tests. Unit tests for `check_host` with a fake resolver (M1, E1, E2, E5, E7), `HashToolFilter` (M2), config validators (M5) and the hub (T2). Integration tests on the #28 fake servers on 127.0.0.1 with `127.0.0.1` on the allowlist: a same-origin 307 makes the connect fail in under 2 s, and a 307 on a mid-session call returns an error outcome (M3), a secret header reaches the fake server from a test env variable and is absent from the captured logs (M4). Existing #28 tests change to the `tools` map form. `server/scripts/gate.sh` passes (M6).
- D10: `docs/security.md` and the servers file example are updated to the new `tools`, `headers` and `OTA_MCP_ALLOWED_HOSTS` format.

## Consequences
- Accepted risk: DNS rebinding. The policy resolves the host, and httpx resolves it again at connect. A hostile DNS server can return a safe IP first and a blocked IP second. Follow-up: an httpcore backend that connects only to the vetted IP (Path 3).
- The owner must copy a hash from the WARNING log into the servers file to approve a tool. A new or changed tool is off until then.
- `NoRedirectTransport` depends on all SDK requests going through `client.send`. The same-origin 307 test is a tripwire for an SDK bump.
- Breaking change to the servers file: `tools` is now a map. #28 is not released, so no migration is needed.
