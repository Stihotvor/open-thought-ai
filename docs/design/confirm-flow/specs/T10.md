# T10: End-to-end confirm tests and gate

## Context
The unit tests of T1 to T8 prove each part. This task proves the whole flow from the session to a fake source, and runs the quality gate (requirements M1 to M5, M7). It is the last M4 safety check before the owner tests in M6.

## Technical Approach
Create `server/tests/test_confirm_e2e.py`. No production code.
- Build a real `DeviceSession` with a fake WebSocket, a real `McpHub` (via the session), a fake `ToolSource` as the MCP tool (confirm True) and the real `DeviceSource` with a fake device socket (`set_volume`). Use a scripted `ReplySource` or a fake `ModelClient` through `VoicePipeline` so a turn asks the tool, with a fake `sleep` (T8) and no real network.
- Run turn 1: the LLM asks the tool. Check the source gets 0 calls, then drive turn 2 with the confirmation transcript through the fake STT.
- Parametrize the yes words (`yes`, `yeah` for en, `tak` for pl, `так` for uk) and the non-yes inputs.
- Then run `server/scripts/gate.sh` and confirm it exits 0 (ruff 0 findings, mypy 0 errors, coverage >= 90 %).

## Acceptance Criteria
```gherkin
Scenario Outline: Nothing runs before the confirmation turn
  Given a fake <kind> tool with confirm True asked by the LLM
  When turn 1 ends
  Then the fake source has 0 calls
  Examples: device | mcp

Scenario Outline: A yes runs the call once
  Given a held call and the session language <lang>
  When the next turn transcript is "<word>"
  Then the source gets exactly 1 call and a second yes turn adds 0
  Examples: en yes | en yeah | pl tak | uk так

Scenario Outline: A non-yes gives 0 calls
  Given a held call in language en
  When the next turn transcript is "<text>"
  Then the source gets 0 calls and the reply is "Cancelled."
  Examples: no | yes but later | empty | tak

Scenario: Timeout
  Given a held call and the fake clock
  When 10 s pass after reply.end
  Then the device gets error confirm_timeout and a later yes runs 0 calls

Scenario: Message order
  Given a held call
  When turn 1 ends
  Then the messages are reply.end, state confirm, confirm.request with timeout_ms 10000

Scenario: The gate passes
  Given all tests
  When server/scripts/gate.sh runs
  Then it exits 0
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
