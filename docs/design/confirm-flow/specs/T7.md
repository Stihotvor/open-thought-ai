# T7: Pipeline: confirmation turn skips the LLM, question ends tool rounds

## Context
A confirmation turn must never reach the LLM, and a held call must end the tool loop with a fixed question (requirements T5, T6, T8, T9, F3, F5). The pipeline only speaks what the hub returns. It serves M1 to M3.

## Technical Approach
Per D8.
- `pipeline.py`, `VoicePipeline._turn`: right after `await notify(text)`, if `tools is not None`, `reply = await tools.confirmation(text)`. If it is not None: build `SentenceFeed`, `feed.put(reply)`, `feed.end()`, do not create the `read_chat` task, and run the same `speak(...)` loop so the text goes through moderation and TTS. Share the `speak` loop with the chat path (one `async with` block, `chat` is None in the confirmation case) and cancel `chat` in `finally` only if it exists. Keep it small.
- `agent.py`, `tool_rounds`: after `messages = [*messages, *await run_tools(...)]`, if `tools.held_question()` is not None, `feed.put(question)` and `return`. No next `chat_turn`. The caller `read_chat` then ends the feed.
- `hub/types.py` `ToolContext` protocol lacks `confirmation` and `held_question`. Resolved: T7 adds `async def confirmation(self, text: str) -> str | None` and `def held_question(self) -> str | None` to `ToolContext` in `hub/types.py`, and updates every `ToolContext` fake in the tests (for example `qa_support.py`, `test_agent.py`, `test_device_tools_e2e.py`).
- Tests: `tests/test_pipeline.py` and `tests/test_agent.py`, with a fake `ToolContext` and the existing fake client.

## Acceptance Criteria
```gherkin
Scenario: A confirmation reply skips the LLM
  Given tools.confirmation(text) returns "Done."
  When a turn runs
  Then "Done." is the spoken chunk and read_chat and chat_turn are not called

Scenario: A confirmation reply is moderated
  Given tools.confirmation returns text
  When the turn runs with a moderation fake that flags it
  Then the turn raises TurnError("moderated") and no audio is yielded

Scenario: No confirmation, normal turn
  Given tools.confirmation returns None
  When a turn runs
  Then read_chat runs as before

Scenario: A held call ends the tool rounds
  Given a chat round that asks one tool, and held_question returns the question
  When tool_rounds runs
  Then the question is the last item put on the feed
  And chat_turn was called once

Scenario: No held call, the loop goes on
  Given held_question returns None after the tool
  When tool_rounds runs
  Then a second chat_turn is made

Scenario: Text before the tool call has played
  Given a first round that streams "One moment." then asks a tool and holds it
  When the feed is read
  Then "One moment." comes before the question
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
