# T6: TurnTools.confirmation, held_question and private _release

## Context
After the hold, the next turn must run the held call once on a yes and cancel it otherwise, with no LLM (requirements T3, T7, T8, T9, E9, F1, F2, F4). The decision lives in the hub, so the pipeline cannot run a call alone. It serves M2 and M3.

## Technical Approach
Per D6 and D7, all in `hub/hub.py`. Uses `confirm_text.py` (T1) and `ConfirmGate` (T2, T5).
- `McpHub._release(self, held: Held) -> ToolOutcome`: runs a chain built once in `__init__` as `build_chain([wrap()], self._terminal)`. No `limit`, no `validate`, no `confirm` (E9). It builds `ToolCall(held.call_id, held.name, held.args)` and `CallCtx(turn=held.turn)`. It never raises (except cancel): catch `Exception`, log, return `ToolOutcome(False, "tool failed", "internal")`. A source failure comes back as an outcome (F1, F2). `_terminal` already handles the timeout.
- `TurnTools.confirmation(self, text: str) -> str | None`:
  1. Return None unless the gate is claimed by `self._ctx.turn`.
  2. `held = gate.pop()` (the gate is empty before the run, so a second yes runs 0 calls).
  3. `is_yes(text, language)`: `outcome = await hub._release(held)`, return `done` text if `outcome.ok`, else `failed` text.
  4. Not a yes: return `cancelled` text.
  5. Any exception (also from `is_yes`): `log.exception`, `gate.drop()`, return `cancelled` text (F4).
  Let `CancelledError` pass.
- `TurnTools.held_question(self) -> str | None`: the fixed `question(language, source, tool)` when the gate holds a call (phase held) whose turn is `self._ctx.turn`. Split `held.name` with `SEP`. Otherwise None.
- `_release` is not on `ToolContext`.
- Tests in `server/tests/test_confirm_release.py`: set the gate to claimed with the T2 methods.

## Acceptance Criteria
```gherkin
Scenario: A yes runs the held call once
  Given a call held in turn 3, armed and claimed by turn 4
  When TurnTools(turn 4).confirmation("yes") is awaited
  Then the fake source gets exactly 1 call with the held args
  And the result is "Done."

Scenario: A second yes runs nothing
  Given the call was released once
  When confirmation("yes") is awaited again
  Then it returns None and the source gets 0 more calls

Scenario Outline: A non-yes cancels
  Given a claimed call
  When confirmation is awaited with "<text>"
  Then the result is "Cancelled." and the source gets 0 calls
  Examples: "no" | "yes but later" | ""

Scenario: Not claimed by this turn
  Given a call claimed by turn 4
  When TurnTools(turn 9).confirmation("yes") is awaited
  Then it returns None and the call stays

Scenario: A failing source after the yes
  Given a claimed call and a source that returns ok False, or a disconnected MCP source
  When confirmation("yes") is awaited
  Then the result is the fixed failure text and nothing is raised

Scenario: A bug fails closed
  Given a claimed call and a _release that raises
  When confirmation("yes") is awaited
  Then an error is logged, the gate is empty and the result is "Cancelled."

Scenario: held_question
  Given a call held in turn 3
  When held_question is read for turn 3 and for turn 4
  Then turn 3 gets the fixed question with "device set_volume" and turn 4 gets None

Scenario: The release does not count
  Given a CallCtx with calls 4 of max 4
  When confirmation("yes") releases a call
  Then it runs and the counter is unchanged

Scenario: _release is private
  Given the ToolContext protocol
  When its members are read
  Then _release is not one of them
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
