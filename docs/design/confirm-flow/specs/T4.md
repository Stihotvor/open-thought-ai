# T4: Turn and language plumbing: CallCtx.turn, McpHub language, turn_tools(turn)

## Context
The held call binds to a turn id (requirements T3), and the yes decision uses the session language with no help from the pipeline (D5). Today `CallCtx` has no turn and `McpHub` has no language. This task adds both. It serves T3 and T7.

## Technical Approach
Per D4 and D5. No behaviour change yet.
- `hub/types.py`: `CallCtx` gets `turn: int = 0`.
- `hub/hub.py`: `McpHub.__init__(self, sources, language: str)` stores `self._language`. `turn_context(self, turn: int) -> TurnTools` returns `TurnTools(self, CallCtx(turn=turn))`.
- `session.py`: `DeviceSession.__init__` gets `language: str = "en"` and passes it to `McpHub([...], language)`. `turn_tools(self, turn: int)` calls `self.hub.turn_context(turn)`. `produce(...)` gets a `turn: int` argument and calls `self.turn_tools(turn)`. `reply(turn, ...)` passes `turn` to `produce`.
- `main.py`: it builds the pipeline with `settings.language`. Check whether a change is needed here. The session language must come from the same setting.
- `server/src/ota_server/gateway.py` builds `DeviceSession(...)`. It must pass `language=settings.language`. Resolved: `gateway.py` is in the `files` list of T4.
- Fix every existing caller and test of `McpHub(...)` and `turn_context()`.
- `tests/test_hub.py`: add a case with a fake `ToolSource` that records `ctx.turn`.
