# T8: Session: arm, 10 s timer, listen.start, abort and close rules

## Context
The session owns the protocol side of the confirm flow: it arms the held call after `reply.end`, asks the device with `confirm.request`, and times out after 10 s (requirements T5, T10, E2 to E7, F5). It serves M4 and M5.

## Technical Approach
Per D9, in `session.py`. The gate is `self.hub.gate` (property from T5).
- `__init__`: add `sleep: Callable[[float], Awaitable[None]] = asyncio.sleep` (injectable clock) and `self.confirm_timer: asyncio.Task[None] | None = None`. Add `CONFIRM_TIMEOUT_S = 10` (`timeout_ms` is 10000) next to the other constants (or in `protocol.py` if it holds protocol constants).
- `play(...)` returns `str`: the `reply.end` reason (`done`, `cap`, `error`). The two early returns (`finish(error)` before speech) return `"error"`.
- `reply()`:
  - Before the `no_speech` pre-filter return, call `self.hub.gate.drop_if_claimed(turn)` (E6).
  - In `try`: `reason = await self.play(...)`. If `reason == "done"`, `token = gate.arm(turn)`. If a token comes back: `await self.ws.send_json({"type": "state", "turn": turn, "state": "confirm"})`, then `{"type": "confirm.request", "turn": turn, "tool": <full name>, "timeout_ms": 10000}`, then `self.confirm_timer = asyncio.create_task(self.expire_later(token))`.
  - `finally` (also on cancel): `gate.drop_if_held(turn)` and `gate.drop_if_claimed(turn)`, before `remember`.
- `expire_later(token)`: `await self.sleep(10)`, then `if gate.expire(token)`: `await self.ws.send_json({"type": "error", "turn": token.turn, "code": "confirm_timeout"})`.
- `handle_text`, `listen.start`: after the `too_many_turns` return (E7) and after `self.turn` is advanced: cancel the timer and `gate.claim(self.turn)` when the gate is armed (E2). If a call is claimed by an older turn (its `listen.stop` never came), `gate.drop()`. Order: drop the stale claim first, then claim.
- `abort` (matching turn) and `close()`: `gate.drop()` and cancel the timer (E3, E4). `cancel_reply` does not drop the gate.
- Cancel the timer task with `contextlib.suppress(asyncio.CancelledError)` and await it.
- Tests in `server/tests/test_session_confirm.py` with a fake WebSocket, a fake reply source that holds a call through a real `McpHub` and a fake `sleep` that the test releases.

## Acceptance Criteria
```gherkin
Scenario: Message order
  Given a turn whose reply holds a confirm call and ends with reason done
  When the session sends its messages
  Then the order is reply.end, state confirm, confirm.request with timeout_ms 10000

Scenario: Timeout
  Given an armed call and a fake clock
  When 10 s pass after reply.end
  Then the device gets error with code confirm_timeout and the turn of the request
  And a later yes runs 0 calls

Scenario: A cut reply gives no request
  Given a reply that ends with reason cap, or with a moderation error after audio started
  When the session ends the turn
  Then no confirm.request is sent and the call is dropped

Scenario: too_many_turns keeps the call
  Given an armed call
  When a listen.start is refused with too_many_turns
  Then the call stays armed and the timeout still fires at 10 s

Scenario: listen.start claims, no_speech cancels
  Given an armed call
  When listen.start arrives, then listen.stop with too little audio
  Then the timer is cancelled, the reply gives no_speech, the call is dropped and no confirm_timeout is sent

Scenario: A claimed call without listen.stop
  Given a claimed call whose listen.stop never came
  When a new listen.start arrives
  Then the call is dropped and a later yes runs 0 calls

Scenario: Abort
  Given an armed call
  When abort arrives for the current turn
  Then the call is dropped and the timer is cancelled

Scenario: Close
  Given an armed or claimed call
  When the session closes
  Then the call is dropped and the timer is cancelled

Scenario: listen.start after the timeout
  Given the timeout has fired
  When listen.start arrives
  Then the turn is a normal turn and confirmation returns None

Scenario: listen.start during the question
  Given a call held and the question still playing
  When listen.start arrives
  Then the call is dropped and a new confirm call in the new turn is held, not confirm_busy
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
