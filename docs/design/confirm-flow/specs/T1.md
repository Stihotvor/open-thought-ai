# T1: confirm_text: fixed texts and is_yes

## Context
The hub speaks fixed texts and decides "yes" without an LLM (requirements T6, T7, T8, T9). This task adds the pure module for both. It serves M2 and M3.

## Technical Approach
Create `server/src/ota_server/hub/confirm_text.py` (pure: no I/O, no state) per D1.
- Language keys are `en`, `pl`, `uk` (same keys as `LANGUAGE_NAMES` in `agent.py`).
- Constants per language: `DONE` ("Done."), `FAILED` ("That did not work."), `CANCELLED` ("Cancelled."). Translate PL and UK.
- `question(language: str, source: str, tool: str) -> str`: the fixed question. It holds the source and the bare tool name, for example "device set_volume". The caller splits the full name with `SEP` (`hub/types.py`).
- `is_yes(text: str, language: str) -> bool`: lowercase, strip punctuation and spaces at both ends, then exact match of the whole text against the yes words of that language only. EN `yes`, `yeah`. PL `tak`. UK `так`. Empty text is False. An unknown language is False.
- Helpers for the other texts: `done(language)`, `failed(language)`, `cancelled(language)`, or one frozen dataclass per language. Pick the smaller one.
- Tests in `server/tests/test_confirm_text.py`: parametrized cases for the scenarios below.

## Acceptance Criteria
```gherkin
Scenario Outline: A yes word is a yes
  Given the language is <lang>
  When is_yes is called with "<text>"
  Then it returns True
  Examples: en "Yes." | en "yeah " | pl "Tak!" | uk "Так."

Scenario Outline: A non-yes is not a yes
  Given the language is <lang>
  When is_yes is called with "<text>"
  Then it returns False
  Examples: en "no" | en "yes but later" | en "" | en "tak" | pl "yes" | uk "tak"

Scenario: Every text exists for every language
  Given the languages en, pl and uk
  When the question, done, failed and cancelled texts are read
  Then each is a non-empty string

Scenario: The question names what runs
  Given source "device" and tool "set_volume"
  When question is called for each language
  Then the text contains "device" and "set_volume"
```

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
