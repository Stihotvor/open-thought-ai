# T2: Held and ConfirmGate state machine

## Context
One held call must outlive its turn and run at most once (requirements T2, T3, E1, E2, E3, E4). The gate is the state holder. Turn ids wrap at 256, so every check binds to the `Held` object. It serves M1 and M2.

## Technical Approach
Create `server/src/ota_server/hub/confirm.py` per D2. No I/O, no asyncio.
- `@dataclass(frozen=True) class Held`: `name: str` (full name), `args: dict[str, Any]` (a copy of the validated args), `call_id: str`, `turn: int`. Frozen with `eq=False`, so identity compares the object, not the turn.
- `ConfirmGate` holds at most one `Held` and a phase: held, armed, claimed.
  - `hold(held: Held) -> bool`: False when a call is already held (the step returns `confirm_busy`).
  - `arm(turn: int) -> Held | None`: phase held with this turn becomes armed. Returns the `Held` as the token. Otherwise None.
  - `expire(token: Held) -> bool`: if the same object is still armed, drop it and return True. Otherwise False.
  - `claim(turn: int) -> bool`: armed becomes claimed by `turn`.
  - `pop() -> Held | None`: only for a claimed call: return it and empty the gate.
  - `drop()`: empty the gate in any phase.
  - `drop_if_claimed(turn)`: drop only a claimed call claimed by `turn`.
  - `drop_if_held(turn)`: drop only a call in phase held whose turn is `turn`. Never armed or claimed.
- Add read helpers the hub needs (T6): `holding_turn() -> int | None` for phase held, and `claimed_by(turn) -> bool`. Keep them minimal.
- Tests in `server/tests/test_confirm_gate.py`.

## Acceptance Criteria
```gherkin
Scenario: Phases follow hold, arm, claim, pop
  Given an empty gate and a Held for turn 3
  When hold, arm(3), claim(4) and pop are called in order
  Then each call succeeds and the gate is empty after pop

Scenario: A second hold is refused
  Given a gate that holds a Held
  When hold is called with another Held
  Then it returns False and the first Held stays

Scenario: Pop is single use
  Given a claimed gate
  When pop is called twice
  Then the first returns the Held and the second returns None

Scenario: Expire acts only on the same armed Held
  Given an armed Held A, then drop, then a new Held B with the same turn, armed
  When expire(A) is called
  Then it returns False and B stays armed

Scenario: Turn wrap
  Given a Held for turn 0 after a wrap at 256
  When expire is called with an older Held for turn 0
  Then it returns False

Scenario: drop_if_held spares armed and claimed calls
  Given a gate in phase armed, then claimed
  When drop_if_held(turn) is called with the Held's turn
  Then the call stays

Scenario: drop_if_claimed binds to the claiming turn
  Given a call claimed by turn 5
  When drop_if_claimed(6) and then drop_if_claimed(5) are called
  Then the first keeps the call and the second drops it
```
