# T3: Confirm flags: no_confirm config, McpSource and DeviceSource

## Context
`ToolSpec.confirm` exists (`hub/types.py`) but no source sets it. MCP tools must fail closed with `confirm=true`, and an operator may opt a tool out (requirements T4, M6). This serves B1 and B2.

## Technical Approach
Per D10.
- `mcp/config.py`: add `no_confirm: list[str] = field(default_factory=list)` to `McpServerConfig`. In `_parse_entry`, read `entry.get("no_confirm", [])`. Add `_check_no_confirm(no_confirm, tools)`: it must be a list of strings, and each name must be a key of the checked `tools` dict. Otherwise raise `ValueError`, so `_try_entry` skips the entry. Pass it to both `McpServerConfig(...)` returns.
- `mcp/source.py`: `_to_spec(server, tool)` gets the `no_confirm` set. Build `ToolSpec(..., confirm=tool.name not in no_confirm)`. `_build_specs` passes `set(config.no_confirm)`.
- `hub/device_source.py`: in `_specs()` set `confirm=True` on `set_volume`. `set_face` and `get_status` keep `confirm=False` (set it explicitly).
- Tests: extend `tests/test_mcp_config.py`, `tests/test_mcp_source.py`, `tests/test_device_source.py`.

## Acceptance Criteria
```gherkin
Scenario: no_confirm names an unknown tool
  Given an entry with tools {"a": pin} and no_confirm ["b"]
  When load_servers reads the file
  Then the entry is skipped and an error is logged

Scenario: no_confirm is valid
  Given an entry with tools {"a": pin} and no_confirm ["a"]
  When load_servers reads the file
  Then the server has no_confirm == ["a"]

Scenario: no_confirm is not a list of strings
  Given an entry with no_confirm "a"
  When load_servers reads the file
  Then the entry is skipped

Scenario: Default MCP specs confirm
  Given a McpSource with tools a and b and no no_confirm
  When specs() is read
  Then both specs have confirm True

Scenario: An opted-out MCP tool does not confirm
  Given a McpSource with no_confirm ["a"]
  When specs() is read
  Then spec a has confirm False and spec b has confirm True

Scenario: Device flags
  Given a DeviceSource
  When specs() is read
  Then set_volume has confirm True, and set_face and get_status have confirm False
```
