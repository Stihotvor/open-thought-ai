## Context
No network call is allowed in tests (T6). An offline pytest guards the example config against F1, F2, and the retry and timeout budget (M1, M2, M3, M5).

## Technical Approach
Write `server/tests/test_litellm_example.py`. Load `docs/examples/litellm/config.yaml` with `yaml.safe_load`, with the path built from `Path(__file__)`. Use typed helpers that pass strict mypy. Tests: (1) each fallback target is a defined `model_name` (F1). (2) Each `api_key` starts with `os.environ/` (F2). (3) The chat chain is exactly `mistral-small-latest`, `chat-gemini`, `chat-local` in order, and STT and TTS each have one speaches fallback (M1). (4) `num_retries <= 1` and `timeout * 3 <= 8` (M3). (5) A no-Gemini variant, built in the test by removing `chat-gemini` from the model list and chain, still ends at `chat-local` and passes check (1). Add no code under `server/src`.

## Acceptance Criteria
Scenario: Fallback targets exist
  Given the example config
  When each fallback target is checked against `model_list`
  Then every target is a defined group, and a config with a wrong target makes the check fail

Scenario: No literal key
  Given the example config
  When all `api_key` values are read
  Then each starts with `os.environ/`, and a config with a literal key makes the check fail

Scenario: Chain order
  Given the example config
  When the `mistral-small-latest` fallback list is read
  Then it equals `["chat-gemini", "chat-local"]`

Scenario: Time budget
  Given `router_settings`
  When `num_retries` and `timeout` are read
  Then `num_retries <= 1` and `timeout * 3 <= 8`

Scenario: No-Gemini variant
  Given a copy of the config without `chat-gemini`
  When the chain is checked
  Then the chain is `["chat-local"]` and all targets are defined

## Definition of Done
- The task's `done_when` check passes.
- Tests exist for every scenario and pass.
- The quality gate reports pass or skipped (never fail).
- No `OPEN:` item remains.
