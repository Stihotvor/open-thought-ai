# T2: providers.py chat_turn with tools

## Context
The LLM must be able to call tools through the `tools` field of `/chat/completions` (T4 constraint, decision D8). Today `ModelClient.chat` sends no `tools` and reads only text. This task adds `chat_turn` and keeps `chat` unchanged for callers. It serves B1, F4 and M7.

## Technical Approach
Edit `server/src/ota_server/providers.py` only. `providers.py` must not import `hub/`. New public names (T5 imports them):
```python
@dataclass(frozen=True)
class TextDelta:
    text: str

@dataclass(frozen=True)
class ToolCallRequest:
    id: str
    name: str
    arguments: str        # the joined JSON text, not parsed here

@dataclass(frozen=True)
class ToolCallsDone:
    calls: tuple[ToolCallRequest, ...]   # ordered by index

MAX_TOOL_INDEXES = 8
MAX_TOOL_ARG_CHARS = 4096   # joined arguments, all calls together

async def chat_turn(self, messages: list[dict[str, Any]], budget: TurnBudget,
                    tools: list[dict[str, Any]] | None = None,
                    tool_choice: str | None = None) -> AsyncGenerator[TextDelta | ToolCallsDone]
```
Rules:
- The body gets `"tools": tools` only when `tools` is not None, and `"tool_choice": tool_choice` only when `tool_choice` is not None. Otherwise the body equals today's body.
- Replace `_sse_delta` by a parser that returns the text and the `tool_calls` deltas of one chunk. Each tool delta has `index`, and may have `id`, `function.name` and `function.arguments`. Join by index: `id` and `name` from the first delta that has them, `arguments` by concatenation.
- Yield each `TextDelta` as it arrives. After `[DONE]`, yield one `ToolCallsDone` only when at least one call was seen. Order is by index. The text limit `MAX_CHAT_TEXT` still applies to text.
- Raise `ProviderError(CHAT)` for: more than 8 distinct indexes, more than 4096 joined argument characters, a delta that is not a dict, an `index` that is not a non-negative int, a call without `id` or `name` at the end, and non-string `arguments`.
- `chat()` keeps its signature `chat(messages, budget) -> AsyncGenerator[str]` and is built on `chat_turn(messages, budget, None)`. It yields `TextDelta.text`. A `ToolCallsDone` in `chat()` raises `ProviderError(CHAT)`.
- Existing tests in `tests/test_providers.py` stay unchanged. Add the new tests there with the same fake transport style.

## Acceptance Criteria
```gherkin
Scenario: Tools field is sent
  Given a fake chat endpoint that records the request body
  When chat_turn runs with a tools list and tool_choice "none"
  Then the body has the same "tools" list and "tool_choice" equal to "none"
  And a call with tools None and tool_choice None has neither key

Scenario: Text then tool calls
  Given a stream with text deltas "Ok." and then tool_calls deltas for index 0 split over 3 chunks
  When chat_turn is read to the end
  Then it yields TextDelta("Ok.") first
  And then one ToolCallsDone with 1 ToolCallRequest whose id, name and joined arguments are complete

Scenario: Two calls by index
  Given deltas for index 0 and index 1 that arrive interleaved
  When chat_turn is read
  Then ToolCallsDone has 2 calls ordered by index

Scenario: Too many indexes
  Given a stream with 9 distinct tool call indexes
  When chat_turn is read
  Then it raises ProviderError with role CHAT

Scenario: Arguments too long
  Given a stream whose joined arguments are 4097 characters
  When chat_turn is read
  Then it raises ProviderError with role CHAT

Scenario: Broken delta
  Given a tool_calls delta with index "x", or without a function name at the end
  When chat_turn is read
  Then it raises ProviderError with role CHAT

Scenario: chat keeps its behavior
  Given the existing chat tests
  When they run without change
  Then they pass
  And chat() with a tool_calls stream raises ProviderError with role CHAT
```
