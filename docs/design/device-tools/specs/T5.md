# T5: reply.py tools kwarg and pipeline tool rounds

## Context
The voice pipeline must let the LLM call tools in rounds and then speak the final text (decisions D7, D9, D10, D11). The pipeline sees only `ToolContext` from T1. This task serves B1, B2, E7, E8, F4, M1 and M7. Text-only turns must behave as before.

## Technical Approach
Use `ToolContext`, `ToolCall`, `ToolOutcome` from T1 (`hub/types.py`) and `chat_turn`, `TextDelta`, `ToolCallsDone`, `ToolCallRequest` from T2 (`providers.py`).

`server/src/ota_server/reply.py`: `ReplySource.__call__` gets the keyword argument `tools: ToolContext | None = None` after `notify`. Import `ToolContext` from `hub/types.py` (`hub/` does not import `reply.py`).

`server/src/ota_server/pipeline.py`:
- Add `MAX_TOOL_ROUNDS = 3`.
- `VoicePipeline.__call__(pcm, history, *, notify=no_notify, tools=None)` passes `tools` to `_turn`, and `_turn` to `read_chat`. `read_chat(messages, budget, feed, clock, tools: ToolContext | None = None)`.
- `read_chat` loops up to `MAX_TOOL_ROUNDS + 1` times. Rounds 1 to 3 call `client.chat_turn(messages, budget, tools.list_tools())`. Round 4 is the final text round and calls `client.chat_turn(messages, budget, tools.list_tools(), tool_choice="none")`. `TextDelta` text goes through the existing sentence cutting into `feed`. At the end of each round, flush the unfinished tail with `feed.put(tail)` and reset it (D11).
- On `ToolCallsDone` (only when `tools` is set): for each `ToolCallRequest` in order, parse `arguments`: empty or blank text gives `{}`, broken JSON gives `None` (the hub rejects it as invalid args). Run `outcome = await tools.run(ToolCall(id, name, args))`. Measure the wait with `budget.clock()` before and after, and call `budget.extend(waited)` (D10). Append to a local copy of `messages` (never to `History`): one assistant message `{"role": "assistant", "content": <text of the round or None>, "tool_calls": [{"id", "type": "function", "function": {"name", "arguments"}}]}`, then one `{"role": "tool", "tool_call_id": id, "content": outcome.text}` per call. Then start the next round.
- A round without `ToolCallsDone` ends the loop: `clock.chat_done()`, then `feed.end()`. Errors still go to `feed.end(exc)` as today, so a broken tool stream gives `llm_failed` (F4). `ToolCallsDone` in the final round, or when `tools` is None, raises `ProviderError(CHAT)`.
- Tool messages and tool results are not added to moderation input. Only the transcript, the reply chunks and the pair are moderated, as today.
- When `tools` is None, keep calling `client.chat` as today, so existing fakes in `tests/test_pipeline.py` still work for text-only turns. When `tools` is set, use `client.chat_turn`.
- `server/src/ota_server/session.py`: change only the `echo` signature to accept `tools: ToolContext | None = None` (ignored), so mypy accepts `echo` as a `ReplySource`. T6 does the rest of the session work.

  Then the fake tool ran once with args {"level": 30}

  Given a fake chat that asks for a tool in every round it may
  When the pipeline runs a turn
  Then there are 3 tool rounds and then 1 text round
  And the text round got the tools list with tool_choice "none"
  And the chat call count is 4

  Given a tool round with outcome text "SECRET-RESULT"
  When the turn ends
  Then the chunks passed to the session contain no tool messages
  And no moderation input contains "SECRET-RESULT"

Scenario: Text before tool_calls is spoken
  Given round 1 streams "Setting it now" without an end mark and then ToolCallsDone
  When the turn runs
  Then "Setting it now" is a spoken chunk
  And it comes before the chunk of round 2

  Given a fake tool that waits 1.0 s on a fake budget clock
  When the tool round ends
  Then budget.extend was called with about 1.0

Scenario: Text-only turn unchanged
  Given tools None or a model that never calls a tool
  When the turn runs
  Then the existing pipeline tests pass without change

Scenario: Echo unchanged
  # Test file: server/tests/test_session.py
  Given the echo reply source
  When it is called with and without tools

  Then the turn ends with TurnError "llm_failed"

Scenario: Bad JSON arguments

  Then tools.run got a ToolCall with args None
  And the loop goes on with the tool message from the outcome
