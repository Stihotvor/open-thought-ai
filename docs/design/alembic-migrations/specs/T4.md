# T4: migrate CLI and startup revision check

## Context
Compose runs `migrate` as a CLI, and `server` must refuse to start on a wrong revision. This serves constraint 4 and the failure modes "revision differs at start" and "accidental downgrade". T5 wires the CLI into compose.

## Technical Approach
- `server/src/ota_server/db/cli.py`: `main(argv)` loads settings, calls `migrate()`. Exit 0 on success, non-zero on any failure. Downgrade only with `--allow-downgrade`. Log lines never hold the URL.
- `server/pyproject.toml`: add a script entry (for example `ota-migrate = "ota_server.db.cli:main"`).
- `server/src/ota_server/db/check.py`: `check_revision(settings)` reads `alembic_version` in the instance schema and compares it with the code head from the script directory. A mismatch, a missing schema, or a missing `alembic_version` table all count as a mismatch (no raw database error). On mismatch raise an error and log both revisions, no URL. Without `database_url` it does nothing (decision rule 9). Use a read-only connection.
- `server/src/ota_server/main.py`: call `check_revision` at startup (lifespan). Keep the change small.
- Tests: `server/tests/test_db_cli.py` and `server/tests/test_db_startup_check.py`, with `migrate` and the connection faked.
- Decision: place the check in the existing `lifespan` in `main.py` (line 46).

## Acceptance Criteria
```gherkin
Scenario: CLI success
  Given migrate is faked to succeed
  When the CLI runs with no flags
  Then the exit code is 0

Scenario: CLI failure
  Given migrate is faked to raise
  When the CLI runs
  Then the exit code is not 0
  And no log line contains the database URL

Scenario: Downgrade needs the flag
  Given the CLI is called with a downgrade request and without --allow-downgrade
  When it runs
  Then the exit code is not 0 and migrate does not downgrade
  And with --allow-downgrade the downgrade is passed to migrate

Scenario Outline: Server start is refused
  Given OTA_DATABASE_URL is set and the state is "<state>"
  When the server starts
  Then the start fails
  And a log line holds the database revision (or "none") and the code head
  And no log line contains the database URL
  Examples:
    | state                    |
    | revision differs         |
    | schema missing           |
    | alembic_version missing  |

Scenario: Revision matches
  Given OTA_DATABASE_URL is set and the database revision equals the code head
  When the server starts
  Then the start succeeds

Scenario: Check is off without a URL
  Given OTA_DATABASE_URL is not set
  When the server starts
  Then no database connection is opened and the start succeeds
```
