# T5: Compose migrate service, test profile, CI job, docs

## Context
This task wires the CLI (T4) and the integration tests (T3) into compose and CI, and updates the docs. It serves constraints 4 and 9 and decision rule 12.

## Technical Approach
- `/compose.yaml`:
  - Add one-shot service `migrate` (same image as `server`, command is the migrate CLI, `restart: "no"`). It connects directly to Postgres, not through a pooler.
  - `server` gets `depends_on: migrate: condition: service_completed_successfully`.
  - Add service `postgres-test`, image `postgres:16-alpine`, `profiles: [test]`.
- `.github/workflows/server.yml`: add a job with a `postgres:16-alpine` service. It sets `OTA_TEST_DATABASE_URL`, then runs `pytest tests/integration` (includes the two-runner test and up/down/up).
- `docs/data-model.md` (decision rule 12): two-key lock `pg_advisory_lock(int4, hashtext(schema))`, lock before schema, CREATE-on-database note for dev and CI, migration session timeouts (`statement_timeout=0`, `idle_in_transaction_session_timeout=0`), direct connection (no pooler), new `settings` defaults (`en`, `''`, `''`, `50`). Move the "pg_dump -n before each migration" line to #34 (safe: 0001 runs on an empty schema).
- `README.md`: name the migrate command and the test profile.
- Do not touch `gate.sh`. It must stay green without Docker.
- Note for #34: the image must carry `pg_dump` before the backup work uses it.

## Acceptance Criteria
