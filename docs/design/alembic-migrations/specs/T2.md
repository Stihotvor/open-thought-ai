# T2: Engine and migrate() flow with Alembic env.py

## Context
Library function `migrate(settings)` is the chosen path (decision, Path 2). It serves constraints 1 to 4 and 7, and the failure modes for lock wait, crash and unreachable database. T3 and T4 call it.

## Technical Approach
- `server/src/ota_server/db/engine.py`: build one engine with `NullPool`, direct to Postgres. Never log the URL.
- `server/src/ota_server/db/migrate.py`: `migrate(settings, *, downgrade=False, allow_downgrade=False)`. Order of calls (decision rules 1 to 6):
  1. Connect. Set `statement_timeout=0` and `idle_in_transaction_session_timeout=0`.
  2. Poll `pg_try_advisory_lock(<fixed int4>, hashtext(:schema))` with the schema as a bound parameter. Bound: 5 min. On timeout raise and log without the URL.
  3. `COMMIT`.
  4. Create the schema only if `to_regnamespace` returns null. Commit.
  5. Set `lock_timeout` for DDL.
  6. `command.upgrade` with `attributes['connection']`, `version_table_schema=ota_<id>`, `transaction_per_migration=False`.
  7. `finally`: `rollback()`, `pg_advisory_unlock`, close.
- Downgrade runs only when `allow_downgrade` is true. Otherwise raise.
- Connection errors: log a line with no URL, re-raise.
- `server/src/ota_server/db/alembic.ini`, `migrations/env.py`, `migrations/script.py.mako`: env.py reads the connection from `config.attributes['connection']`. It holds no schema name beyond the `version_table_schema` passed in.
- Test: `server/tests/test_db_migrate.py` with a fake connection and `caplog`. Make the lock bound injectable so the test is fast.
- Decision: the fixed first lock key is the constant `LOCK_APP_KEY = 0x4F544149` (ASCII "OTAI"), named in `migrate.py`.

## Acceptance Criteria
```gherkin
Scenario: Call order on a fresh database
  Given a fake connection where the lock is free and to_regnamespace returns null
  When migrate runs
  Then the recorded calls are in this order: session timeouts, pg_try_advisory_lock, COMMIT, schema create, lock_timeout, upgrade, rollback, pg_advisory_unlock, close

Scenario: Existing schema is not created again
  Given a fake connection where to_regnamespace returns a value
  When migrate runs
  Then no CREATE SCHEMA call is recorded

Scenario: Lock is polled and the schema is a bound parameter
  Given a fake connection where the lock is busy for two polls, then free
  When migrate runs
  Then pg_try_advisory_lock is called three times with (int4, hashtext(:schema))
  And the schema name is passed as a bound parameter, not in the SQL text

Scenario: Lock wait exceeds the bound
  Given a fake connection where the lock is always busy and the bound is short
  When migrate runs
  Then it raises an error
  And no caplog line contains the database URL
  And no upgrade call is recorded

Scenario: Unreachable database
  Given the connect call raises an operational error
  When migrate runs
  Then it raises an error
  And no caplog line contains the database URL

Scenario: Upgrade fails
  Given the upgrade call raises
  When migrate runs
  Then rollback, pg_advisory_unlock and close are still recorded in that order
  And the error propagates

Scenario: Downgrade needs an explicit flag
  Given migrate is called for a downgrade with allow_downgrade false
  When it runs
  Then it raises an error and records no downgrade call
```
