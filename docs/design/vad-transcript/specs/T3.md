# T3: Wire VAD and notify into pipeline, update docstring

## Context
The pipeline must skip STT for silence (B2, E1, E2), send STT the trimmed audio (E3), and send the transcript after STT and moderation (B1, E4, E6). It uses `trim_speech` from T1 and the `notify` port from T2. This closes issue #21 (B3).

## Technical Approach
In `server/src/ota_server/pipeline.py`, `__call__`:
- Use the keyword-only `notify: Notify = <no-op>` parameter that T2 adds to the signature (from `reply.py`).
- Run `trim_speech` first, before `check_moderation`, through `asyncio.to_thread` like `wav_to_pcm`.
- None gives `TurnError("no_speech")` with no provider call. `ValueError` gives `TurnError("internal")`.
- STT gets the trimmed audio. Empty STT text gives `no_speech` and no notify (E5).
- After transcript moderation passes, `await notify(text)`. Pass the full text. The session truncates to 200 (T2). A flagged text gives `error moderated` and no notify (E6).
- Chat gets the full text (E4).
- Replace the docstring line "Not yet here: the `transcript` message and VAD." with a short VAD and transcript note.
- Add tests in `server/tests/test_pipeline.py` with fake providers only.
