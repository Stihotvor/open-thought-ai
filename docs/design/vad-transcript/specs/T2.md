# T2: Add notify port: Notify type, ReplySource Protocol, echo and fakes, session transcript send

## Context
The device must see the `transcript {turn, text}` message after STT and before the reply (B1, T3, M5). Path 2 gives the pipeline an outbound `notify(text)` port that the session supplies. This task builds the port and the session send. T3 uses it.

## Technical Approach
- `server/src/ota_server/reply.py`: add `Notify = Callable[[str], Awaitable[None]]` and a no-op default. Make `ReplySource` a Protocol with `__call__(pcm, history, *, notify: Notify = <no-op>)`. Add the keyword-only `notify` param with the no-op default to `echo`. Behaviour of `echo` does not change.
- `server/src/ota_server/session.py`: `produce` always passes `notify=` a per-turn closure. The closure sends `{"type": "transcript", "turn": turn, "text": text[:200]}` only while `open_turn == turn`. The `MIN_SPEECH` check in `reply` stays.
- `server/tests/test_gateway.py` and `server/tests/test_session.py`: every fake reply source gets the same keyword-only `notify` param with the no-op default, so mypy accepts them.
- Add a test in `test_session.py` with a fake source that calls `notify("x")`, and one with text over 200 characters.
- F3: a failed send raises. Add no new error path.

## Acceptance Criteria
```gherkin
Scenario: Transcript is sent while the turn is open
  Given a fake source that calls notify("hello") then yields reply audio
  When the device sends a full voice turn
  Then the device gets {"type": "transcript", "turn": <turn>, "text": "hello"}
  And it arrives before reply.start

Scenario: Transcript text is truncated
  Given a fake source that calls notify with 300 characters
  When the turn runs
  Then the transcript text is the first 200 characters

Scenario: No transcript after abort
  Given a fake source that waits, then calls notify("x")
  And the device sends abort before the call
  When the source calls notify("x")
  Then the device gets no transcript message for that turn

Scenario: Echo is unchanged
  Given the echo source
  When the existing echo tests run
  Then they pass without edits to their assertions
  And the device gets no transcript message

Scenario: Fakes accept notify
  Given all fake sources in test_gateway.py and test_session.py
  When mypy runs
  Then it reports 0 errors
```
