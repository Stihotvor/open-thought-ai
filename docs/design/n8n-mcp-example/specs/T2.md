# T2: Offline test for the MCP servers guide

## Context
The guide (T1) can drift from the code. This test fails CI when a setting name, the JSON example or the structure drifts. It serves the Success Metrics in `requirements.md`. T1 and T2 land in one commit.

## Technical Approach
File: `/home/yevhend/claude-projects/open-thought-ai/server/tests/test_mcp_servers_guide.py` (new). Mirror `server/tests/test_litellm_guide.py`: module docstring, `REPO = Path(__file__).resolve().parents[2]`, `GUIDE_PATH = REPO / "docs" / "guides" / "mcp-servers.md"`, constants `MAX_SETUP_STEPS = 6` and `MAX_LINES = 120`, a `guide` fixture that reads the file as UTF-8, plain test functions with `-> None`. Strict mypy: type every argument (`tmp_path: Path`, `monkeypatch: pytest.MonkeyPatch`).

Imports: `from ota_server.mcp.config import PIN, SECRET_VAR, load_servers` and `from ota_server.config import Settings`.

Helper `_first_json_block(guide) -> str`: regex `` r"```json\n(.*?)```" `` with `re.DOTALL`, first match.

Tests:
1. `test_guide_line_limit`: `len(guide.splitlines()) <= MAX_LINES`.
2. `test_guide_setup_steps`: take `guide.split("## Setup steps", 1)[1].split("\n## ", 1)[0]`. Collect numbers as in the litellm test. Assert `1 <= len(numbers) <= MAX_SETUP_STEPS` and `numbers == [str(n) for n in range(1, len(numbers) + 1)]`.
3. `test_example_loads`: write the first json block to `tmp_path / "servers.json"`. Call `monkeypatch.setenv("MCP_SECRET_N8N", "x")` (the real env var named in the example). Call `load_servers(str(path))`. Assert `len(servers) == 1`. Assert `name == "n8n"`, `transport == "http"`, `url.startswith("https://n8n.example.com")`, `headers == {"Authorization": "MCP_SECRET_N8N"}`. Assert `tools` is not empty. Note: `load_servers` does not read the env var itself, but the test sets it so the example matches real use. Note that a rejected entry gives `[]`, so the length check catches every config error.
4. `test_example_pins_and_no_confirm`: for `server = servers[0]` assert every pin in `tools.values()` matches `PIN` and every `no_confirm` entry is in `tools`. Parse with `json.loads` too, so the check runs on the raw block and shows the key sets in the failure message.
5. `test_guide_setting_names_exist`: assert `"mcp_servers_file"` and `"mcp_allowed_hosts"` are in `Settings.model_fields`, assert `"OTA_MCP_SERVERS_FILE"` and `"OTA_MCP_ALLOWED_HOSTS"` are in the guide, build the name as `Settings.model_config["env_prefix"] + field.upper()`. Also: every `MCP_SECRET_[A-Z0-9_]+` match in the guide fully matches `SECRET_VAR`. Every `OTA_[A-Z0-9_]+` token in the guide must equal `env_prefix + name.upper()` for a name in `Settings.model_fields` (no invented settings).
6. `test_guide_has_no_invented_n8n_identifiers`: parametrize over the denylist `["n8n-nodes-langchain", "mcpTrigger", "toolWorkflow", "/webhook/", "/mcp-test/"]`. Assert `value not in guide`.
7. `test_guide_names_required_text`: parametrize over `["Troubleshooting", "OTA_MCP_ALLOWED_HOSTS", "no_confirm", "see your n8n UI", "current hash sha256:"]`. Assert `value in guide`.

Limits: no network, no n8n, no file writes outside `tmp_path`. Coverage: this test file adds no source lines to measure. The gate is `server/scripts/gate.sh`.

RESOLVED: the log text is `current hash %s` with the value `sha256:...` (server/src/ota_server/mcp/toolfilter.py:69), so `current hash sha256:` matches the real WARNING line.
