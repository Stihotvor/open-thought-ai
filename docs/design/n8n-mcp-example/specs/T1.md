## Technical Approach
Files: `/home/yevhend/claude-projects/open-thought-ai/docs/guides/mcp-servers.md` (new) and `/home/yevhend/claude-projects/open-thought-ai/README.md` (one line).

Guide layout, in this order. The heading names are fixed because T2 splits on them.
- `# MCP servers: n8n example`. Two sentences: any MCP server works the same way. n8n is the worked example.
- `## Setup steps`: numbered `1.` to at most `6.`, one step per line start, no sub-numbering. Cover: (1) create the n8n workflow and attach tools through the Custom n8n Workflow Tool node, add an MCP Server Trigger, pick the auth (none, bearer, header or OAuth2) and copy the URL (all three marked "see your n8n UI"); (2) write the servers file; (3) set `OTA_MCP_SERVERS_FILE`, `OTA_MCP_ALLOWED_HOSTS` and `MCP_SECRET_N8N` in `.env`; (4) start the hub and read the WARNING log line `current hash sha256:...` for each tool; (5) copy each hash into `tools`; (6) restart and call the tool by voice.
- The first fenced `json` block in the file is the servers file example. It must hold exactly one server: `name` `n8n`, `transport` `http`, `url` `https://n8n.example.com/<placeholder>` (the path is a placeholder marked "see your n8n UI"; no `?query`, no user info), `headers` `{"Authorization": "MCP_SECRET_N8N"}`, `tools` with at least two keys and dummy pins `sha256:` plus 64 hex digits, and `no_confirm` with a subset of the `tools` keys. Keep `timeout` out or inside 1 to 60.
- Later `json` or `bash` blocks are allowed. Put the env lines in a `bash` block, never in a second `json` block.
- `## Troubleshooting`: a list, each item "symptom: fix". Items: tool missing or silent (pin missing or wrong, copy `current hash sha256:...`); tool vanished after an edit in n8n (the description changed, the hash changed, update the pin); n8n on a LAN or private address (add the host to `OTA_MCP_ALLOWED_HOSTS`); config load fails (`no_confirm` names a tool that is not a key of `tools`); n8n down at start (the hub starts without the n8n tools, 5 s deadline, no error for the user); bearer secret missing (set `MCP_SECRET_N8N`, never write the secret in the servers file).
- Required literal strings: `Troubleshooting`, `OTA_MCP_SERVERS_FILE`, `OTA_MCP_ALLOWED_HOSTS`, `MCP_SECRET_N8N`, `no_confirm`, `see your n8n UI`, `current hash sha256:`.
- State only n8n facts from the requirements: SSE and streamable HTTP, auth none, bearer, header or OAuth2, Custom n8n Workflow Tool node. Do not write the node type id, a real URL path or a workflow JSON. Do not use these identifiers: `n8n-nodes-langchain`, `mcpTrigger`, `toolWorkflow`, `/webhook/`, `/mcp-test/`.
- Hard limit: 120 lines or less. STE style.

README: add `- [MCP servers (n8n example)](docs/guides/mcp-servers.md)` directly after the speech guide line (`README.md:18`). Exactly one occurrence of `guides/mcp-servers.md`.

Do not touch `docs/design/mcp-client/decision.md:29`. It is a follow-up (see `decision.md`, Consequences).
